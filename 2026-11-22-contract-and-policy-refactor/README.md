# Core、JS 与 App 契约及策略收敛计划

日期：2026-11-22。状态：**实施中**。设备及插件自定义事件、外发传输状态与进度、上传会话、testkit 基础管线、插件版本策略、错误边界和注册表已接入。逐项证据和剩余工作见[实施记录](./IMPLEMENTATION.md)。

本目录针对局部功能修复后留下的条件分支、简化算法、硬编码和错误兜底重新梳理。判断依据是当前调用链和实际契约，不根据注释语气推测作者动机。计划以消除重复规则、补全状态与资源生命周期为目标。

## 2. 重新梳理后的根因

| 根因 | 当前表现 | 负责收敛的位置 |
| --- | --- | --- |
| 用主界面消息替代插件契约 | 模式被忽略、信封层级不一致、设备回调读错形状 | App 插件事件投影 + core/JS 契约 |
| 页面承担宿主状态责任 | 传输中间态永久缓存、结束记录删除后无可靠查询 | 宿主传输状态服务 |
| 资源操作缺少状态模型 | 分块写入竞态、会话失效后残留、依赖页面 best effort 清理 | 上传会话服务 |
| mock 按方法各自补齐 | 权限拼写、支持查询、调用记录、离线设备语义漂移 | testkit 执行管线 + 跨实现用例 |
| 局部输入代替领域模型 | 手写多套版本比较、若干快捷键白名单 | 单一版本语义、结构化按键模型 |
| 文案和兜底替代类型 | 字符串猜 trap、英文句子判配置状态、未知失败归为 unsupported | 类型化错误与业务原因 |
| 展示状态代替平台事实 | 窄窗口和触屏被当成移动宿主 | 宿主环境与布局分离 |

## 4. 实施批次

1. **建立边界**：07、09，以及 11 的最小跨边界测试夹具。先让失败和配置状态可可靠识别。
2. **贯通事件和传输**：01 → 02；03 单独提交，再与传输 worker 接管集成。每次契约变更同步 Rust、JS 类型、注入构建物与测试。
3. **修正测试替身**：04 的明显偏差先修；事件、传输部分跟随第二批完成。不能等所有生产改造结束才开始修 mock。
4. **收敛领域策略**：05、06、08、10 各自按职责提交。跨仓库依赖固定到已经验证的提交。
5. **整体验收**：执行 11 的联合场景，更新既有专题和当前状态，仅把实际通过的部分标记为完成。

## 5. 共同约束

- 核心继续不依赖 Tauri、Vue 或 WebView；无界面也成立的版本、状态转换和授权规则归 core。
- App 维护窗口、IPC 传输、页面会话与宿主资源适配；UI Store 只消费宿主事实。
- `@synra/client`、`@synra/protocol` 保持当前类型包定位。暂不为本次改造引入新的通用运行时包。
- 合法的平台分支、明确的资源上限、未实现 API 的显式拒绝本身不是缺陷。收敛规则来源，不把所有常量改成可配置项。
- 不为未发布的 Rust/App 接口保留双路径兼容层；同步真实调用方。JS 包可能有外部使用者，实际改变公开 API 前按其发布流程记录行为变更。
- 不把“没有收到事件”“注册表无记录”解释为业务成功；不通过关闭检查、放宽授权或万能 mock 让测试通过。
- 手写源文件遵守所在仓库的 300 代码行约定，按责任拆分，不按语法堆入通用工具文件。
