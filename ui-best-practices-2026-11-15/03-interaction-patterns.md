# 交互模式
## 6. 交互模式

### 6.1 页面头部

页面头部只保留：标题、范围/分类、一个主动作、一个更多入口。安装、扫描、开始配对等动作使用主色；发布者管理、导出、清理记录等低频操作进入更多菜单。

同一上下文不出现两个同等强调的主按钮。危险动作放在确认流程或菜单末尾，按钮文字使用明确动词，例如“忘记设备”“移除插件”“停止会话”。

### 6.2 摘要、详情和 Drawer

- 摘要行：名称 + 短说明 + 主要状态 + 一个高频动作。
- 详情：完整字段、权限、调用记录、故障原因和恢复动作。
- Drawer：适合连续查看对象，不适合复杂多步安装。
- Modal：只用于短决策，例如同意/拒绝配对、确认移除、保存权限变化。
- 多步安装、更新和权限编辑使用完整流程面，不嵌套多个 Modal。

打开详情后保留列表筛选、滚动位置和触发按钮焦点；关闭后回到原位置。通知跳转使用稳定对象 ID，不把临时表单内容放进 URL。

### 6.3 搜索和命令入口

全局搜索负责“去哪里”，页面内搜索负责“在这里找什么”，注册表搜索负责“远端发现什么”，三者必须使用不同标题和范围提示。

桌面保留 `Ctrl/Cmd-K` 命令入口；移动端提供可见的搜索按钮。结果按页面、设备、插件、设置分组，选中后直接进入对象详情。输入法组合状态下不能误提交；Escape 关闭后焦点回到触发入口。

### 6.4 反馈层级

| 情况 | 反馈方式 |
|---|---|
| 成功保存、复制、启用 | 原位置短反馈，不打断当前上下文 |
| 进行中的网络或文件操作 | 进度行或状态条，保留取消 |
| 需要用户决定 | 全局待处理提示或明确 Modal |
| 可恢复失败 | 就近显示原因和重试/修复动作 |
| 不可恢复失败 | 保留诊断 ID、错误码和下一步 |
| 后台状态变化 | 更新摘要和未读计数，不自动抢焦点 |

提示不能只写“失败”或“完成”，也不能只靠颜色表达状态。

### 6.5 动作收纳与布局稳定

低频动作进入“更多”，桌面端可以由对象行的父级 hover 展示动作簇；键盘使用 `:focus-within`，触摸端使用稳定的更多按钮或 Bottom Sheet。动作区需要预留宽度，显示/隐藏只改变 opacity、颜色和可用性，不改变行高、正文宽度或滚动位置。

加载、错误、未读、权限变化和更新提示使用稳定槽位或顶部通知层。不要在正文中间用条件渲染临时插入一整段消息；短提示通过固定顶部的 `NoticeHost`/Popover 展示，持续性错误留在对应对象的固定反馈槽中。完整规则见[布局稳定与渐进披露](./09-layout-stability-and-disclosure.md)。
