# 布局稳定与渐进披露

> 目标：让默认界面保持简洁，同时让低频操作可发现、可访问，并且不因条件元素突然出现而改变页面整体宽高。

## 1. 设计原则

### 1.1 默认视图只承担当前任务

默认状态只显示：

- 对象名称和必要身份信息；
- 当前状态；
- 一个主要动作；
- 一个稳定的更多入口或动作区；
- 用户继续操作所必需的反馈。

低频、危险、技术性或管理性动作进入“更多”。例如忘记设备、拉黑、清除历史、导出诊断、发布者管理和移除插件，不应该和“打开”“配对”“启用”等高频动作并列。

### 1.2 渐进披露不能依赖 hover

父级 hover 可以作为桌面端的快捷展示方式，但必须有等价的输入方式：

| 输入环境 | 展示方式 |
|---|---|
| 精确指针 | 父级 `:hover` 显示动作簇 |
| 键盘 | 父级 `:focus-within` 显示动作簇，Tab 可进入每个动作 |
| 触摸/粗指针 | 显示稳定的“更多”按钮，点击后打开 Popover/Bottom Sheet |
| 屏幕阅读器 | 通过可访问名称读出对象和动作，不能只依赖视觉 hover |

动作簇需要有清楚的父级关系。可以是行、卡片或列表项，但不应让用户猜测“悬停哪里才会出现按钮”。可用 `aria-label`、可见的更多图标、焦点样式和位置稳定的动作区辅助发现。

### 1.3 条件展示不应改变页面几何

加载、成功、错误、未读、权限新增、更新提示和可选按钮都属于状态变化。它们可以改变内容，但不应让页面主内容突然向下跳动、左右变宽或改变滚动位置。

实现时优先使用以下方式：

1. **预留槽位**：对象行、页面头部和工具栏提前保留状态/动作区域的高度和宽度。
2. **叠加层**：提示、Popover、短暂反馈和全局消息使用 fixed/sticky/portal 层，不进入正文流。
3. **稳定容器**：加载 skeleton 与最终内容使用相同的块尺寸；错误信息放进已有的状态区域。
4. **局部替换**：只替换对象所在的状态字段，不插入新的页面级段落。
5. **保留滚动锚点**：异步更新后保持用户正在看的对象和滚动位置；只有用户主动请求才跳到最新。

避免用 `v-if` 在页面中间临时插入一大段提示、按钮或说明。若内容必须进入文档流，应在初始结构中预留同等高度，并保证空状态、加载态、成功态和失败态共享同一个容器。

## 2. 父级 hover 动作区

### 2.1 推荐结构

```text
对象行
┌──────────────────────────────────────────────────────────┐
│ 图标  名称       描述/目标                 状态   [动作区] │
│                                              [打开] [⋯]  │
└──────────────────────────────────────────────────────────┘
```

- 动作区拥有稳定的最小宽度；按钮默认可隐藏，但不能让正文重新占用这块空间。
- 桌面端 hover/focus-within 时显示动作区；过渡只改变 opacity 和颜色，不改变 width、height 或 padding。
- 动作区覆盖在预留区域内，不能覆盖对象名、状态和错误文本。
- 低频动作集中到一个“更多”菜单；菜单内部按“查看/管理、更新/同步、危险操作”分组。
- 主动作可以保持常显；不要把唯一的“打开”“同意”“保存”藏在 hover 中。

### 2.2 交互状态

```text
默认：动作区占位稳定，主动作或更多按钮可见
hover：动作簇淡入，行背景轻微变化
focus：与 hover 相同，同时显示清晰焦点环
pressed：菜单或按钮保留按下反馈
disabled：保留位置，说明不可用原因
loading：只替换当前动作的内容，不隐藏整行
```

动作区不应因为名称变长、状态变为错误或切换语言而改变行高。按钮文字变长时优先换行或进入菜单，不能把对象行撑成不同高度。

### 2.3 触摸和移动端

移动端没有可靠的 hover。触摸布局必须显示一个稳定的更多按钮，或者允许点击整行打开详情，再从详情页执行低频操作。不能把桌面 hover 动作直接变成“长按才出现”。

Popover/Bottom Sheet 的打开和关闭不应改变页面正文高度；关闭后回到原触发按钮。菜单超过一个屏幕时只滚菜单正文，标题和关闭动作保持可达。

## 3. 稳定布局规则

### 3.1 页面头部

页面头部固定三块：

```text
标题区（稳定） | 轻量筛选区（可为空但保留结构） | 主动作/更多区（稳定）
```

扫描中、更新可用、未保存草稿和权限待处理等状态只更新已有区域。不要在标题下方临时插入一条横幅把列表整体推下去。

### 3.2 对象列表

- 行高由最坏的正常内容决定，而不是由某个瞬时状态决定。
- 状态徽标使用固定的状态列、绝对定位或预留 inline slot。
- 错误摘要最多一行；完整原因进入详情或顶部通知。
- 加载态、空态和错误态使用同一列表容器，不在列表外新增页面级面板。
- 新对象进入列表时使用局部高亮，不能让整个列表重排或自动滚动。

### 3.3 表单和设置

- 每个设置行的标签、当前值、控件和反馈位置稳定。
- 保存成功、保存失败和需要重新读取都放在行内反馈槽中。
- 不因保存成功突然添加“已保存”大横幅；短反馈可显示在顶部通知层。
- 变更冲突使用已有的冲突提示槽，不插入新的页面段落。

### 3.4 加载和异步状态

- 预估小于 200ms 的操作不显示闪烁 spinner。
- 长操作显示进度，但进度容器从操作开始就占位。
- 结果返回时只更新对应对象；不要让全页从 skeleton 重新布局。
- 网络重连、设备上线和事件补发不自动抢焦点、不自动滚动页面。

## 4. 顶部通知层

提示消息、复制结果、保存结果、后台更新和短暂错误统一进入顶部通知层或顶部 Popover，不把短暂消息插进当前页面正文。

### 4.1 位置和结构

```text
┌───────────────────────────────────────────────┐
│ 顶部通知层：成功 / 警告 / 错误 / 待处理         │  ← fixed/sticky
└───────────────────────────────────────────────┘
页面内容从稳定的起始位置继续渲染
```

- 桌面端位于窗口顶部内容区内侧，移动端避开 safe-area 和系统状态栏。
- 使用 `position: fixed`、`sticky` 或 Teleport/portal，避免消息进入页面文档流。
- 多条消息垂直堆叠，但设置最大数量；更早消息进入通知中心或折叠计数。
- 通知层不覆盖当前 Modal、配对请求和键盘输入；由全局 overlay coordinator 决定 z-index 和焦点。
- 短消息自动消失，重要错误和待处理请求保持到用户处理或明确关闭。

### 4.2 内容和可访问性

- 消息先写结果，再写原因和下一步，例如“插件已启用。打开插件查看页面”。
- 通过 `aria-live="polite"` 读出普通状态；错误或需要决定的消息使用更高优先级，但不能频繁抢焦点。
- 通知必须提供文本，不只显示颜色或图标。
- 消息中的“重试、查看、撤销”是明确动作；不要把整条通知做成没有名称的可点击区域。
- 关闭通知不会取消后台任务，除非消息明确表示它本身就是任务控制。

### 4.3 与页面内反馈的边界

| 反馈类型 | 位置 |
|---|---|
| 复制成功、保存成功、已启用 | 顶部短通知或按钮短暂变更 |
| 某一行的字段错误 | 对应行的稳定反馈槽 |
| 当前流程必须决定 | 全局待处理区或 Modal |
| 诊断错误和长原因 | 详情面或终端元数据面板 |
| 后台任务进度 | 首页活动区或任务行，不使用 Toast 代替进度 |

## 5. 与现有组件的落点

| 现有位置 | 设计调整 |
|---|---|
| `App.vue` / `NoticeHost` | 将短通知从主内容流移到固定顶部通知层；保留全局事件订阅 |
| `PluginRow`、`DeviceRow` | 引入稳定动作区和父级 hover/focus-within 展示；移动端显示更多按钮 |
| `PageHeader` | 固定标题、筛选、主动作和更多区的几何槽位 |
| `ErrorNotice` | 普通短错误走顶部通知；需要持续处理的错误留在稳定局部槽位 |
| `PairingPrompt`、`TransferPrompt` | 保持 Modal/全局待处理层级，不让提示插入页面正文 |
| `DebugConsole` | 使用独立 Sheet/Dock；打开关闭不改变页面内容高度 |
| `SettingsRow` | 统一保存、冲突、重新读取和错误反馈槽位 |

终端头部只保留 `● LIVE` 和关闭按钮；暂停、清空、复制等低频操作放进过滤行的更多菜单。终端正文必须保留独立的垂直触摸滚动区域，不能因为 Sheet、scrim 或父级手势处理而吞掉 Android WebView 的 `touchmove`。

## 6. 验收清单

- [ ] 默认页面只显示当前任务、状态、一个主动作和稳定的更多入口。
- [ ] 桌面 hover、键盘 focus、触摸点击和屏幕阅读器都能访问低频动作。
- [ ] 动作出现/隐藏不改变行宽、行高、页面滚动位置或正文换行。
- [ ] 状态徽标、错误、未读计数和更新提示都有稳定槽位。
- [ ] 通知消息显示在顶部层，不把正文向下推，也不覆盖当前 Modal 的操作。
- [ ] 窄屏没有依赖 hover 或长按才能发现的功能。
- [ ] 加载、成功、失败、重连和异步补发不会让页面整体跳动。
- [ ] 200% 缩放、长中文、长英文和长 ID 下，动作区仍可达且不遮挡对象信息。
- [ ] reduced-motion 下只保留必要的状态变化，不使用位移或持续闪烁传达关键内容。
- [ ] 终端头部只显示 LIVE 和关闭；低频终端操作进入更多菜单。
- [ ] Android WebView 能通过手指上下滑动终端内容，且回看历史时不会被自动滚回底部。
