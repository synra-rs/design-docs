# 目标体验、视觉语言与跨端布局
## 3. Synra 的目标体验

### 3.1 五个设计目标

| 目标 | 具体含义 |
|---|---|
| 安静但有反馈 | 正常状态少打扰，异常和待决定状态能被快速发现 |
| 高密度但可扫描 | 一行先看到对象、状态和下一步，技术字段按需展开 |
| 可预测 | 同一种动作在页面、菜单、Drawer 和移动端使用相同语义 |
| 可恢复 | 取消、失败、离线、权限变化和窗口关闭都保留准确结果 |
| 有工具感 | 终端、搜索、诊断和任务状态像工作台工具，不像临时拼出来的弹窗 |

### 3.2 页面层级

```text
应用壳
├─ 一级导航：首页 / 设备 / 插件 / 设置
├─ 全局待处理：配对、传输、权限、插件更新
├─ 当前页面：页面标题、一个主动作、轻量筛选
├─ 对象摘要：名称、状态、一个高频动作、更多菜单
├─ 对象详情：权限、历史、技术字段、恢复动作
└─ 全局工具面板：搜索、synra://wire、诊断导出
```

页面不应同时承担对象详情、帮助文档、安装流程和诊断日志。每个层只回答一个问题：在哪里、当前对象是谁、现在发生什么、下一步能做什么。

## 4. 视觉语言

### 4.1 颜色和表面

继续以 `@synra/theme` 为唯一真相源，增加明确的语义层：

| 层级 | 用途 | 视觉方向 |
|---|---|---|
| `screen` | 应用背景 | 稳定、低纹理、避免大面积渐变 |
| `surface` | 页面主要内容 | 清晰边界、少量圆角 |
| `raised` | 对象行、轻面板 | 只在需要区分层级时使用 |
| `overlay` | Drawer、Modal、Popover | 明确覆盖关系，不能和页面内容混淆 |
| `terminal` | 线缆监视器 | 不透明的近黑背景，避免毛玻璃透出正文 |

颜色优先表达状态：在线/运行、等待、警告、错误、离线。不要给每种事件或每个插件分配独立颜色，否则用户必须先查图例才能读懂界面。

### 4.2 字体和密度

- 页面标题保持中等字重，不用超大标题制造“产品感”。
- 对象名、状态和主动作使用同一行层级；说明和技术字段退到次级层。
- 普通对象行的目标高度为 56–72px，内容增长时允许自然变高。
- 桌面按钮可以紧凑，但触控命中范围至少 44×44px；不能把小图标本身当成命中区域。
- 只在终端、ID、地址、时间和事件名使用等宽字体。
- 说明文字宁可减少重复，也不要靠更小、更淡来压缩页面。

### 4.3 Icon 规则

保留 Carbon 图标体系和 UnoCSS 图标类，但统一以下规则：

1. 导航图标必须配文字；窄侧栏只有在有 tooltip、焦点名称和足够命中范围时才可折叠。
2. 图标按钮必须有可访问名称；无文字动作不能只靠颜色或悬停提示。
3. 常规图标使用 16px 或 20px；对象类型和大空状态使用 24px 或 32px。
4. 同一上下文只使用一种线宽和视觉重量；不要混用手绘 SVG、双色插图和 Carbon 系统图标。
5. 图标颜色默认跟随文字；只有状态、危险动作或当前选中状态才使用语义颜色。
6. 不使用“装饰性图标墙”填充空状态；空状态先说明当前没有内容和下一步。

建议建立一个 `icon-map.ts`：集中维护页面、状态和动作的图标映射，禁止页面内临时拼写图标类名。

## 5. 响应式和跨端布局

### 5.1 采用“同一任务，不同编排”

| 空间 | 布局 | 交互重点 |
|---|---|---|
| ≥1280px | 展开侧栏 + 单内容区；对象详情可 Drawer 或并排 | 键盘快捷键、批量扫描、快速跳转 |
| 1024–1279px | 展开侧栏或窄栏 + 单内容区 | 保证完整操作，不为填满空间强行分栏 |
| 768–1023px | 窄栏 + 单内容区 | 图标导航带 tooltip，详情使用覆盖层 |
| <768px | 底部四入口 + 单主视图 | 详情全屏、底部动作、原生返回和 safe-area |

响应式只做五种变化：重新定位、缩放、重排、显示/隐藏、重新架构。禁止通过横向滚动保存桌面版布局；小屏优先保留任务目标、状态和主动作。

### 5.2 跨端交互一致性

- 桌面 `Esc`、移动端返回、Drawer 关闭和页面返回都要对应同一个“离开当前层级”语义。
- 所有异步动作都有“开始、进行中、完成、失败、取消”状态；不能用弹窗消失推断成功。
- 键盘、鼠标、触摸和屏幕阅读器都能到达主动作；拖拽、长按和多指手势必须有普通点击替代路径。
- 移动端底部导航保持 4 个一级入口；不把诊断终端变成第五个永久 Tab。
