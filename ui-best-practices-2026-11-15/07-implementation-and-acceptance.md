# 实施、验收与边界
## 10. 实施顺序

### Phase 0：统一基础

- 建立表面、状态、密度、动效和图标 token。
- 清理页面内临时 icon class、重复按钮样式和不一致的错误颜色。
- 为桌面/窄窗口/移动端建立同一组截图视口。

### Phase 1：壳层与终端

- 保持四个一级入口。
- 完成全局搜索和 `synra://wire` 的 Dock/Sheet 形态。
- 补齐焦点进入、焦点归还、Escape、暂停、复制、跳到最新和 reduced-motion。

### Phase 2：设备与首页

- 先改摘要行、状态层级和空状态。
- 完成 A/B 配对对话框、失败和取消状态。
- 验收两台设备不同角色、长名称、离线和重复请求。

### Phase 3：插件工作台

- 已安装/发现分离。
- 列表、详情、权限、安装流程拆分。
- 复用现有权限和更新契约，不在 UI 再造授权判断。

### Phase 4：设置与跨端收口

- 统一 SettingsRow 密度和局部反馈。
- 检查 Android 返回、safe-area、软键盘和底部导航。
- 在 Windows WebView2 与 Android WebView 上完成同一批场景回归。

## 11. 验收清单

### 交互

- [ ] 每个页面首屏只有一个主任务和一个主动作。
- [ ] 0、1、多项数据，以及加载、成功、失败、取消、离线状态都有明确画面。
- [ ] 打开详情、Drawer、Modal 后，关闭可以回到原对象、筛选和焦点。
- [ ] 键盘、鼠标、触摸和屏幕阅读器可以到达同一主路径。
- [ ] 危险动作有明确名称和可恢复/不可恢复说明。
- [ ] 搜索、终端过滤和注册表搜索不互相混淆。

### 视觉

- [ ] 图标风格、尺寸、颜色和对齐来自同一映射。
- [ ] 不使用大面积渐变、持续闪烁或无意义 skeleton。
- [ ] 终端背景、事件方向色、状态色在深浅主题下都可读。
- [ ] 200% 缩放、长中文、长英文、长 ID 和窄窗口不横向溢出。

### 动效

- [ ] 动效只说明空间/状态关系，不承载唯一信息。
- [ ] `prefers-reduced-motion` 下关闭位移、回弹和持续动画。
- [ ] 终端日志不逐行动画；大量事件不会造成视觉抖动。
- [ ] 任务进度和错误反馈不依赖 Toast 消失时间。

### 终端

- [ ] 打开、关闭、Escape、遮罩、焦点归还完整。
- [ ] 暂停不丢计数，回看历史时不自动滚底。
- [ ] 新日志出现时有未读计数和“跳到最新”。
- [ ] 复制、选择、搜索和屏幕阅读器模式可用。
- [ ] 传输高峰期间不会挤压设备卡、配对提示和任务状态事件。

### 布局稳定与渐进披露

- [ ] 低频动作收进更多；桌面 hover、键盘 focus 和触摸入口语义一致。
- [ ] 动作区、状态徽标、错误和未读反馈都有稳定槽位，显示/隐藏不改变页面几何。
- [ ] 短提示进入顶部通知层，不将正文向下推；重要错误仍有固定的局部处理位置。
- [ ] 异步响应、重连和事件补发不会抢焦点、重置滚动或让整页重新布局。
- [ ] 窄屏不依赖 hover/长按发现功能，触摸端更多按钮和 Bottom Sheet 可达。

## 12. 不做什么

- 不替换现有组件库，不为了追求“新”而引入第二套设计系统。
- 不把 Node Modules Inspector 的依赖图、市场首页或黑底终端直接复制到 Synra。
- 不把调试终端变成命令执行器，也不在终端中显示 payload 正文。
- 不增加新的一级页面来承载搜索、终端、任务或诊断；它们属于全局工具或当前页面的辅助面。
- 不用动画掩盖后端状态不准确、权限语义不清或空状态信息架构问题。
