# Synra UI 交互设计梳理

> 日期：2026-10-29。交付类型：**研究、现状审查与后续实施设计**；本轮没有改应用代码。
> 参考：[Folo](https://github.com/RSSNext/Folo)，重点是交互与信息组织；保留 Vue 3、Ant Design Vue、UnoCSS、`@synra/theme`。
> 现状基线：`synra-app@759af79`；Folo 源码基线：`68edee907003a90877f2ffa6bd9ed9bedababfd4`。

## 1. 结论

现在的问题主要是**信息没有分层、不同任务混在一页、空状态与说明占据太多空间**，继续降低文字亮度无法解决。
推荐采用“稳定导航 → 紧凑列表 → 按需详情 → 明确确认”的组织方式：默认看结果，进入对象后再管理，执行敏感操作前再说明影响。

Folo 值得借鉴的是：列表与详情分工、短小工具栏、次要操作进入更多菜单、辅助信息延迟出现、设置分类、命令与快捷键的一致入口。
不照搬阅读器的三栏数量、浅色外观、AI 区域或业务功能，也不更换组件库。

## 2. 本轮约束与设计状态

| 状态 | 内容 |
| --- | --- |

| ✅ 用户已明确 | 保留组件库；减少常驻文本与过于明显的介绍；参考 Folo 的巧妙交互；文档放在本目录 |

| 🟡 后续增强 | 列表与详情并排、全局查找/命令入口、设置定位、按真实测量决定列表虚拟化 |
| 🔴 尚未定义完整契约 | 持久任务历史及任务/传输/文件关联；不作为首批界面整理的前置条件 |

这里的“必须”描述**目标实现的验收条件**，不表示这些交互已经实现。不要把文档截图当成改版后的界面。

## 4. 推荐的目标结构

```text
Synra
├─ 首页：需处理事项 / 进行中 / 当前任务 / 接收记录
├─ 设备：已配对 / 附近设备 / 配对流程 / 设备详情
├─ 插件：已安装 / 发现 / 插件详情 / 安装流程 / 发布者管理
└─ 设置：通用 / 设备与安全 / 插件与来源 / 诊断 / 关于
```

保留四个一级入口；页内分类负责缩短长页面。不上来就增加“控制台、中心、市场、任务中心”等重叠概念。
插件详情属于宿主管理；插件自己的功能界面继续通过“打开”进入独立 WebView，不能嵌回首页或管理详情。

## 5. 最值得先做的七件事

1. 首页多个大空状态改成短状态行，让有内容的任务先出现。
2. 插件页默认只看已安装列表，安装表单在点击“安装插件”后出现。
3. 插件权限、审计、配额放到对应插件详情，异常摘要与待授权状态保留在列表。
4. 设备列表保留名称与可理解的连接状态，地址、标识与取消配对进入详情/更多菜单。
5. 配对变成明确的邀请/回复流程，只有需要时展示相应说明与输入框。
6. 设置按目的分类，避免“高级设置”展开后再次变成长页面。
7. 所有 hover 优化同时支持 focus 与点击；触摸端保留可见入口，关键操作不依赖 hover。

本轮不包含发版、部署、复制 Folo 源码或替换现有产品视觉。后续实施不需要为尚未发布的旧 UI 状态保存兼容分支。
