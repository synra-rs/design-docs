# Synra UI 交互设计梳理

> 日期：2026-10-29。本目录包含研究、现状审查与实施设计；**当前开发进展见[11](./11-current-progress.md)**。
> 参考：[Folo](https://github.com/RSSNext/Folo)，重点是交互与信息组织；保留 Vue 3、Ant Design Vue、UnoCSS、`@synra/theme`。
> 现状基线：`synra-app@759af79`；Folo 源码基线：`68edee907003a90877f2ffa6bd9ed9bedababfd4`。

## 1. 目标：专业软件的整体完成度

**2026-10-29 用户澄清：希望 Synra 有专业软件的感觉，解决当前像 Demo 的观感；列表与否不重要，Folo 的做法需要时才参考。**
因此本目录首先以 [00 · 专业软件的完成度标准](./00-product-quality-bar.md) 评判页面：目的明确、构图合理、视觉一致、操作可靠、各种状态完整、不同环境下自然可用。

当前的信息堆叠、重复说明和空状态占位，是整体完成度不足的表现；不能只靠改成列表、降低文字亮度或多加 hover 解决。
Folo 提供交互思路；列表、卡片、分栏、就地展开、Drawer 都按任务选择，没有固定模板。

## 2. 本轮约束与设计状态

| 状态 | 内容 |
| --- | --- |
| ✅ 用户已明确 | 主程序是通用宿主；插件业务留在独立插件页面；示例状态、插件标识、调用记录允许展示 |
| ✅ 用户已明确 | 保留组件库；减少常驻文本与过于明显的介绍；参考 Folo 的巧妙交互；文档放在本目录 |
| ✅ 用户再次澄清 | 首要目标是专业软件的完成度；不要求列表化或照搬 Folo 的页面形式 |
| ✅ 现有规范继续生效 | 单一主题来源、中英文、可见焦点、触控可达、视口内独立滚动、权限由内核强制 |
| 🟡 可选方案，按页取舍 | 概览、设备分组、按需配对、对象详情、设置分类、更多菜单与 hover；采用前说明解决什么问题 |
| 🟡 后续增强 | 列表与详情并排、全局查找/命令入口、设置定位、按真实测量决定列表虚拟化 |
| 🔴 尚未定义完整契约 | 持久任务历史及任务/传输/文件关联；不作为首批界面整理的前置条件 |

这里的“必须”用于功能正确性、可达性与安全等验收条件；具体页面形式属于候选方案，并非强制实现。不要把文档截图当成改版后的界面。
已有规范以 [28](../28-app-ui.md) 为准；本目录细化 R54–R56。需要改变旧规则的地方在实施前同步更新规则：
例如未来并排详情对滚动区的扩展、设置分类内恢复位置，不能以新文档静默覆盖旧行为。

## 4. 功能归属示意

以下描述功能放在哪里，不要求把所有分组做成页签、列表或独立详情：

```text
Synra
├─ 首页：需处理事项 / 进行中 / 当前任务 / 接收记录
├─ 设备：已配对 / 附近设备 / 配对流程 / 设备详情
├─ 插件：已安装 / 发现 / 插件详情 / 安装流程 / 发布者管理
└─ 设置：通用 / 设备与安全 / 插件与来源 / 诊断 / 关于
```

保留四个一级入口；页内分类负责缩短长页面。不上来就增加“控制台、中心、市场、任务中心”等重叠概念。
插件详情属于宿主管理；插件自己的功能界面继续通过“打开”进入独立 WebView，不能嵌回首页或管理详情。

## 5. 优先改善的七个结果

1. 四页的页面宽度、对齐、字号、间距与控件密度形成一致的视觉秩序。
2. 首页在没有任务、少量内容和繁忙时都有合理重心，不靠大空插图撑页面。
3. 插件页围绕查找、使用与管理组织内容，不像安装接口和权限表单的展示集合。
4. 设备的身份、连接与操作自然组合，具体用卡片、面板或行按内容决定。
5. 配对等多步任务有清楚的下一步、等待、取消、失败与完成反馈。
6. 说明、技术字段与高级管理不干扰日常使用，必要信息仍可完整读取和操作。
7. 鼠标、键盘、触摸、中英文和不同窗口尺寸下，体验保持连贯可靠。

本轮不包含发版、部署、复制 Folo 源码或替换现有产品视觉。后续实施不需要为尚未发布的旧 UI 状态保存兼容分支。
