# 12 · 全局线缆监视

> 2026-11-02。回答：调试用的数据流放在哪、长什么样、为什么是终端，以及它不能影响什么。
> 实现：`synra-rust-app/src/components/DebugConsole.vue`、`src/debug/wire.ts`；
> 后端：`synra-observe::wire` 与 `synra-ipc` 的 `debugWire` 事件。

## 1. 问题

配对、发现与传输出问题时，界面只给一句「联系不上」或「没反应」，真正的原因在协议帧里：

- 广播的端口和监听的端口是不是同一个；
- 请求发出去了没有，对面回的是拒绝还是超时；
- 连接在握手、信封还是传输块上断的。

这些事实不属于某一个页面。放在设备页，用户在设置页遇到「什么都没发生」时就看不到；做成开发者工具，
又要求用户先知道去哪打开。所以入口必须**全局常驻**，内容必须能**按原样读**。

## 2. 入口：浮动气泡

- 固定在窗口右下角；桌面距边 24px，移动端抬到底部导航之上。
- 直径 52–54px，主色渐变加一圈微光；它是页面上唯一高饱和的控件，因为它是诊断入口，不是普通操作。
- 有新行且抽屉关着时显示未读计数（最多 `99+`），并播放一次 900ms 的扩散环。
- `aria-label` 与 `title` 都是「打开线缆监视」，焦点环用白色外描边，保证在深色渐变上可见。

不把入口放进侧栏或页头：那会让它随导航形态变化而消失，也会让它看起来像某个页面的功能。

## 3. 抽屉：由下往上

- 遮罩淡入（220ms），面板从 `translateY(102%)` 到 `0`（280ms，`cubic-bezier(0.22,1,0.36,1)`）。
- 桌面高度 `min(72vh, 42rem)`，左右留 20px 并保留顶部圆角；移动端满宽、高 `min(78vh, 46rem)`。
- 顶部只有一行：标题 `线缆 synra://wire`、上/下行计数与总行数、暂停/清空/复制/关闭。没有副标题——「双向的每一帧」只是把标题又说了一遍。
- 第二行是过滤器：全部 / 发送 / 接收，右侧提示 `Esc 关闭`。
- `Esc` 关闭；点遮罩关闭；关闭后焦点回到气泡（实现上由浏览器默认焦点顺序保证，不额外抢焦点）。

面板是毛玻璃（`blur(22px) saturate(135%)`）叠在近黑底上。终端本身用不透明 `#080c12`：透明画布在
WebView 里会因合成层差异出现纯黑块，和面板材质对不上。

## 4. 终端

用 `@xterm/xterm` + `@xterm/addon-fit`，与参考实现（antfu/node-modules-inspector）和 `peon-hall` 的
命令抽屉同一套渲染器。理由不是「像终端」，而是：

- 等宽对齐让「时间 · 方向 · 对端 · 事件 · 字节数」五列可扫；
- ANSI SGR 是终端自己的颜色协议，颜色和文本在同一条字符串里，不需要另一套 HTML 结构和样式；
- 滚动、选择、复制、回看是终端已经解决的问题。

终端只读（`disableStdin: true`），8000 行回滚，12px 等宽字体，行高 1.35。
xterm 与它的样式在**首次打开抽屉时**才动态加载：它约占 300KB JavaScript，不该由每个只看首页的人承担。
首屏因此保持约 190KB（gzip 62KB），终端被拆成按需块。

### 一行长什么样

```text
22:18:41.871 → 7f3a9c21  _synra.pair.request  128B
22:18:42.191 ← 7f3a9c21  _synra.pair.response  42B
22:18:42.771 • 7f3a9c21  dial 192.168.0.42:47100
```

| 部分 | 颜色 | 说明 |
| --- | --- | --- |
| 时间 | 灰 `SGR 90` | 本机时区，精确到毫秒；同一秒内两帧是常态 |
| `→` | 青 `38;5;45` | 本机发出 |
| `←` | 绿 `38;5;120` | 本机收到 |
| `•` | 琥珀 `38;5;220` | 生命周期标记，不是帧 |
| 对端 | 紫 `38;5;177` | 设备 id 前 8 位，`local` 表示本机 |
| 事件 | 白 `97` | 线协议事件名、`chunk #n`、或标记文本 |
| 字节 | 灰 `90` | `B / KB / MB`，标记行没有 |

颜色只由方向决定，不按事件类型分配：读者先判断「谁说的」，再读事件名。给每类事件一个颜色会让图例变成必需品。

### 空状态

终端中央一行灰字「还没有流量。扫描、配对或发送点什么。」不画插画、不放按钮：这个抽屉不是引导页。

## 5. 数据从哪来

`synra-observe::wire` 是进程级的观测点，`PeerLink` 在每次成功写出、每次解析出帧后调用它：

- 信封：事件名与 payload 字节数；
- 传输块：`chunk #n` 与字节数；
- 握手：`hello` / `hello ack`；
- 心跳：`ping` / `pong`；
- 生命周期：`dial <地址> · <名字>`、`dial failed · <原因>`；
- 发现：每次查询广播一行、每台被听见的设备一行（含地址），不逐包展开。

它**只观测**：拿到的是已经写出的字节或已经解析的帧，不能改写、拒绝或延迟一次收发。没有安装 sink 时，
`emit` 只做一次 `Option` 判断，不格式化字符串。

界面安装 sink 后，每条转成 `KernelEvent::DebugWire` 走既有事件总线。选择事件总线而不是第二条 Tauri 通道，
是因为界面已经有且只有一个事件入口；多一条通道就多一处顺序、重连和版本偏移要维护。

### 不能挤掉真正的状态

一次传输是成千上万个块。逐块上报会塞满内核的**有界**事件总线，可能让设备卡或配对提示被丢弃 ——
调试功能不能和它观察的对象抢带宽。所以：

- 信封、握手、心跳、标记全部上报；
- 传输块最多每 200ms 一条；一行仍能看出传输在动，但不占据队列。

这是刻意的不完整：监视器显示的是**消息与关键帧**，不是每一个 64KB 块。需要逐块核对时用抓包工具，
不是这个抽屉。

## 6. 交互细节

- **暂停**：停止写入，但计数继续；恢复后新行继续出现，暂停期间的行不补写。适合读一段已经滚过去的日志。
- **清空**：清终端缓冲、挂起缓冲与计数，不改变过滤器。
- **复制**：把整个缓冲按行取出，去掉行尾空白；成功/失败在按钮上显示 1.5 秒。走 WebView 的
  `navigator.clipboard`，失败时明确说「复制失败」，不静默。
- **过滤器**：只影响之后写入的行，不回放历史。历史已经在终端里，重排会让「刚才看到的那一行」消失。
- **打开时**：先把抽屉前挂起的行按当前过滤器写入，再 `fit()`；动画结束后 280ms 再量一次，
  否则列数按动画中途的高度算。写入后滚到底部。

## 7. 验收

- 手机与桌面都能打开、关闭、`Esc` 关闭；抽屉不遮住气泡入口（打开时气泡隐藏）。
- 无流量时显示空状态，不显示 0 行计数以外的假数据。
- 配对一次，能看到 `dial · 地址`、`_synra.pair.request`、`_synra.pair.response` 或 `dial failed · 原因`。
- 传输一个文件，块行不超过每秒 5 条；设备卡和配对提示不因传输而停止更新。
- 深色与浅色系统主题下文字可读；焦点环可见；触控目标不小于 44px。
- 打包产物中不存在 `?wire-demo=1` 的演示行。

## 8. 非目标

- 不是开发者工具：不提供任意 JS、REPL、断点或注入。
- 不记录 payload 正文：终端是传输视图，复制消息内容会把调试台变成第二个数据副本。
- 不替代诊断导出：导出是给维护者的持久证据，抽屉是给现场的人看「刚刚发生了什么」。
