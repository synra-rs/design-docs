# 10 · 实施批次与验收

## 1. 完成定义

本目录交付设计依据与实施说明，不表示改版已经上线。后续每一批完成需满足：功能入口没有丢、状态语义没有变、键盘和触摸都可用、正常页面确实变简洁、性能未因隐藏内容而退化。
文档/原型不代替实际浏览器与 Native 验收；不以 jsdom 中存在某个类名证明布局正确。

## 2. 分批建议

| 批次 | 改动 | 依赖 | 本批应可独立交付 |
| --- | --- | --- | --- |
| A · 去除常驻噪声（P0） | 首页紧凑摘要/空状态；插件安装流程按需出现；更多菜单整理；统一标题和说明层级 | 04、09；现有 Modal/Dropdown 即可 | 四页完整可用；没有新后端契约 |
| B · 插件详情（P0/P1） | 已安装/发现分类；插件详情Drawer；权限/更新/审计/发布者入口归位；通知直达 | A；共享动作执行入口 | 所有现有插件管理能力仍可达，正常行不再是巨型表单 |
| C · 设备和配对（P1） | 已配对/附近分组；按需配对流程；设备详情与取消配对菜单 | 现有配对store；04 | 两种角色和无目标导出均可用，安全语义不变 |
| D · 设置与系统反馈（P1） | 设置分类、局部错误、异常定位、细化性能生命周期；全局任务反馈与手机布局 | 现有配置/凭证/通知store | 无功能丢失，关闭诊断后无无效轮询 |
| E · 宽屏连续操作（P2） | 列表/详情并排；同页选择和返回保留位置；可选设置定位 | B–D＋壳层布局契约更新 | 1024px仍可用，宽屏提高连续浏览效率 |
| F · 管理查找与性能增强（P2） | 可见的全局查找入口、Ctrl/Cmd-K、已有对象/设置定位；测量后决定虚拟化/分页 | 共享动作与稳定选择 | 不新增插件业务命令注册协议，不预建昂贵搜索索引 |
| G · 持久活动（另立契约） | 若需要统一最近活动，补终态/分页/关联/清理契约后再做UI | 协议与内核查询、数据保留定义 | 不能用前端本地数组伪造持久历史 |

每批可拆成有意义的小提交，英文 Conventional Commit、仅subject、GPG签名，按既有授权推送；不发版、不打标签、不部署。
先做 A，再做 B/C/D；E/F/G 不是整理好当前页面的前置条件。

## 3. 代码边界

- 页面读取既有 store；详情开关、当前分类、表单草稿是 UI 状态，不复刻内核运行状态。
- `src/events.ts` 仍是全局事件唯一订阅者；打开每个详情不得注册第二个 Kernel channel listener。
- DTO 来自 `@synra/protocol`；新增历史契约改真相源再生成，不能在 `.vue` 手写一个理想返回类型让编译器闭嘴。
- 共享动作只统一调用、可执行条件、busy和错误，不复制内核权限/信任规则。
- 通用结构先按真实重复提取；不建设新的组件库、不改插件业务仓库去配合宿主布局。
- 未发布阶段直接重构，不为旧 UI 选择/内部数据格式新增兼容层。

## 4. 全功能去向检查

实现 PR/提交说明应对照下表逐一确认，菜单收纳不等于删除能力。

| 原有能力 | 新位置 | 关键不变量 |
| --- | --- | --- |
| 当前任务候选选择/拒绝 | 首页待处理/任务详情 | 关键决策常显、动作对象准确 |
| 传输进度/取消 | 首页进行中 | 不提前删行、保留取消确认策略 |
| 接收文件元数据 | 首页接收记录/详情 | 不恢复文件打开/删除业务入口 |
| 扫描/停止扫描 | 设备页头 | 实际结果和失败可区分 |
| 导出邀请/listen/connect/取消 | 配对流程 | 无目标导出保留，真实握手阶段不跳过 |
| 取消已建立配对 | 设备更多/详情＋确认 | 不顺带清理其他数据或权限 |
| 目录/包/注册表安装 | 安装流程 | 来源显式，签名/权限语义保留 |
| 注册表搜索/排序/分页 | 发现分类 | 未配置/无结果/失败分开 |
| 启用/停用/打开/重试 | 插件行＋详情 | 打开不等于启用，状态来自内核 |
| 权限决策/查看授权 | 插件权限详情 | 新增权限不默认同意，结果不造假 |
| 检查更新/更新 | 插件菜单/概览 | 发布者/新增权限检查不绕过 |
| 同步计划与结果 | 插件详情流程 | 部分成功可见，不默默授权 |
| 审计分页/清除 | 插件调用记录 | 按需读取、清除明确确认 |
| 发布者信任管理 | 插件发布者入口 | 完整指纹可核对，决定语义分开 |
| 移除及数据选择 | 插件更多＋确认 | 默认保留数据，残留错误可见 |
| 所有既有偏好/来源/保留期限 | 对应设置分类 | 原key、默认、校验及生效方式正确 |
| 身份修复/清理/重启提示 | 设备与安全＋全局摘要 | 异常不会因分类未选中而消失 |
| 指标/日志/环境检查/崩溃/导出 | 诊断分类 | 有界、按需、局部失败，隐私选项清楚 |
| 托盘/系统通知/独立插件窗口 | 原生表面 | 语言一致，主程序关闭与退出有别 |

## 5. 测试效率：按变更面验证

文档单独提交不跑 Rust/前端全量单测；检查相对链接、证据文件、Markdown结构和 `git diff --check`。
开发迭代先跑涉及页面/store/交互单测；纯样式与内容位置调整以真实浏览器截图/操作为主要证据，不写只断言utility类的测试。
抽象动作、异步请求竞态、权限/确认语义、定时器生命周期值得写行为测试，不能仅以快照“按钮还在”证明。

阶段提交前按受影响面执行：

| 变更面 | 必须检查 | 无需重复的内容 |
| --- | --- | --- |
| 宿主前端批次 | 相关行为测试、全量前端阶段门禁、ESLint、类型/生产构建、shapes、真实浏览器 | 没有Rust改动且无新失败时不重复全量Rust |
| 主题token/适配 | 主题对比度/适配守卫＋宿主实际渲染 | 不靠只刷新截图代替对比度计算 |
| Native/Rust | 适用的目标测试、格式/Clippy、no-default tests与default check；实测窗口行为 | 没变的成功检查无理由不反复跑 |
| 协议/历史契约 | 生成物与边界守卫、内核集成、前端类型与场景 | 不修改生成文件冒充源修改 |

先读结果再提交，不能把测试和commit串在一个忽略退出码的命令里。失败修复后只重跑受影响与阶段必要检查。

| 维度 | 最少覆盖 |

只有可见入口减少而同等功能路径仍可用，才算“简洁且不影响功能”。

## 7. 性能原则与测量

以下是**目标/预算，尚未测量达成**；先记录基线硬件、构建模式、数据量、样本数，再判定。

| 场景 | 约束/建议预算 | 怎样验证 |
| --- | --- | --- |
| hover 快捷入口 | 不发IPC/网络，不初始化索引；100个已有对象扫过不新增请求 | mock调用计数＋浏览器Network/性能记录 |
| 静态详情打开 | 已有快照内容无需等待网络；可见反馈建议在100ms内 | 生产构建测输入到可见反馈，多次取分位数 |
| 审计/日志 | 打开才请求，条数/字节有界，关闭不继续拉取 | 调用计数、快速切对象、异常/取消测试 |
| 性能页 | 离开/折叠/窗口不可见后不再触发指标轮询 | fake timer＋实际IPC记录，不只看组件是否隐藏 |
| 列表更新 | 按稳定ID更新，不因进度事件重挂载所有行 | Vue性能记录、焦点/滚动稳定性 |
| 长列表 | 100项仍可顺畅筛选/选择；1000项压力测后再决定虚拟化 | 长任务、布局开销、内存、读屏和焦点成本一起评估 |
| 搜索 | 本地筛选不调用远端；远端请求去抖/显式提交，旧响应不能覆盖 | 请求数量和竞态测试 |
| 时钟/资源 | 时间格式器共享，timer不随每行无界增长；打开关闭详情20次资源回落 | 活跃timer/listener、堆快照趋势，避免将一次GC波动判为泄漏 |
| 构建 | 每批记录JS/CSS体积；新增依赖必须有实际收益 | 构建报告、diff，不为仅几个命令引完整索引框架 |

不凭“隐藏了内容”就声称性能提升：如果所有详情仍 `force-render` 并执行查询，只是视觉隐藏，成本还在。
虚拟化必须同时考虑可访问性、选中项和焦点、动态行高、返回位置；没有测量瓶颈时先用有界分页/按需渲染。
不先优化Rust业务路径；只有界面测量显示瓶颈跨过IPC后再跟踪相应内核查询。
