# 03 · 壳层、导航与信息架构

> 🟡 布局候选与共用约束。沿用 [28 R11–R16、R54–R56](../28-app-ui.md)，以 [00](./00-product-quality-bar.md) 的整体完成度为目标。
> 下文的列表/详情是适合高密度管理的一种方案；没有足够收益时保留单内容区、卡片或就地展开，不要求实施分栏。

## 1. 各层只回答一个问题

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 应用壳 | 当前页面、全局连接/异常、当前设备、顶层导航 | 插件业务、每个对象的完整属性 |
| 页面头部 | 页面名称、范围/分类、一个主要入口 | 多段介绍、所有表单和所有操作 |
| 列表 | 辨认对象、看到状态、选择对象、一个高频动作 | 展开每个对象的权限、日志、标识和高级配置 |
| 对象详情 | 这个对象的完整状态、属性、权限、历史入口 | 第二个独立业务状态副本 |
| 确认流程 | 本次操作的目标、影响、选择与结果 | 通用帮助长文、默认扩权、后台静默改变动作 |

一级入口继续为首页、设备、插件、设置；设置保留独立路由，不改成唯一可达的浮动弹窗。
当前侧栏底部设备名称保留，平台和版本降低优先级；完整版本/设备 ID 在设置“关于/设备与安全”可查。

## 2. 目标框架

```text
┌──────────────┬───────────────────────────────────────────┐
│ Synra        │ 页面标题             主动作        更多   │
│              ├───────────────────────────────────────────┤
│ 首页         │ 分类 / 轻量筛选                           │
│ 设备         ├──────────────────────┬────────────────────┤
│ 插件         │ 对象列表             │ 所选对象详情       │
│ 设置         │                      │ 需要时才出现       │
│              │ 区域内滚动           │ 区域内滚动         │
├──────────────┤                      │                    │
│ 当前设备     │                      │                    │
└──────────────┴──────────────────────┴────────────────────┘
```

这是信息结构示意，不是要求每一页常驻三栏。首批优先整理现有“导航＋单内容区”；若确实需要完整对象管理，可选择 Drawer、就地展开或独立页面。宽屏分栏仅在连续对照有价值时采用。
首页和设置没有必要为对称而增加空详情栏。

## 3. 尺寸与响应式

保留现有断点，不引入 880、1100 等特殊断点，也不采用未经验证的容器查询。
以下尺寸是实现起点，验收以内容可用和实测为准；现有 token 有等价值时直接复用。

| 视口 | 导航 | 列表与详情 | 控件与文字 |
| --- | --- | --- | --- |
| `<640` | 底部四入口 | 一次一个主视图；详情全宽、明确返回/关闭 | 点击目标 ≥44px，工具栏换行，输入与主要按钮可独占行 |
| `640–767` | 底部四入口 | 不强行分栏；设置分类可用 Select | 表单标签与输入按空间堆叠 |
| `768–1023` | 现有 96px 图标栏 | 列表＋覆盖式 Drawer；内容不被挤成窄条 | 图标栏名称支持 tooltip/focus |
| `1024–1279` | 现有 240px 展开侧栏 | 仍以列表＋Drawer 为主 | 桌面最小窗口也能完整操作 |
| `≥1280` | 展开侧栏 | 插件等对象页可并排；列表建议不窄于320px，详情不窄于420px | 不够宽就退回 Drawer，不放开横向溢出 |

普通表单内容宽度建议 640–768px，长列表/详情工作区建议上限约1200px；首批不必改变所有页面宽度。
现有全局 `max-w-3xl` 不能原封不动包住未来并排工作区：应由页面声明“阅读/表单宽度”或“工作区宽度”，壳层不猜页面 DOM。
不为了填满 1904px 大屏把控件无限拉开，也不把所有页面居中到巨大左右空白中。

## 4. 滚动职责

1. 文档/根壳固定在视口内，不让页面内容撑高整个应用。
2. 侧栏品牌与当前设备固定，只有菜单区在溢出时滚动。
3. 单内容模式只保留一个页面纵向滚动区，表格/卡片不各建小滚动条。
4. 并排模式由页面框架分配列表区和详情区各自的剩余高度；外层内容不再同时形成第三层纵向滚动。
5. 页面头部和当前分类可固定；较高的错误内容不能把可用内容挤到零，应归属相应滚动区。
6. Drawer/Modal 的正文可滚动，标题、关闭与确认操作不被长权限列表挤出视口。

`min-h-0`、`min-w-0`、`minmax(0,1fr)`、`overflow` 要沿完整父子链核对；只给最内层 `overflow-auto` 不算实现。
滚动条占位、overscroll 是增强，不能成为内容可达的前提。仍须检查主区和详情的 `scrollWidth/clientWidth`。

## 5. 路由、选择与返回

| 状态 | 推荐存放位置 | 规则 |
| --- | --- | --- |
| 顶层页面 | 当前 hash 路由 | 保持现有四入口 |
| 插件选择 | 现有 `/plugins?plugin=<id>` 查询参数 | 保留通知直达；打开对应详情，无效 ID 给轻提示与返回列表 |
| 页内分类/对象选择 | 需要深链接的用 query；短时筛选在页面 UI 状态 | 参数名称统一，不把敏感邀请、路径、诊断内容放 URL |
| 权限/安装/配对表单草稿 | 对应流程组件 | 切语言/开帮助不丢草稿；换目标时隔离草稿 |
| 设备/插件/任务状态 | 已有 Pinia store / IPC 契约 | 不因打开详情再维护第二份相互漂移的列表 |
| 菜单、tooltip、hover 预览 | 组件本地 | 不持久化，不进入浏览器历史 |

首次切换顶层页面仍按 R54 从顶部开始；同页打开/关闭详情应保留列表位置和筛选。
设置分类是否恢复各自位置随分类实现明确落地，不允许浏览器 Back 一次退掉一个 tooltip。
手机返回优先关闭当前详情/流程，再返回列表；关闭只改变 UI，不暗中取消正在运行的配对/安装/传输任务。

## 6. 可见层与焦点

正常同一时刻只保留一个对象详情；确认框可在其上出现一层，不嵌套第二个详情 Drawer。
Tooltip 不夺取焦点；菜单 Escape 后回触发器；Modal/覆盖式 Drawer 管理焦点并在关闭后归还。
并排详情不是模态，不锁焦点，用户可以直接 Tab 回列表。

列表不是随意套 `role=listbox`：包含开关/按钮的管理行可采用语义列表＋具名的“查看详情”入口。
不要在 `<button>` 内嵌其他 `<button>`；整行可点击时仍须提供独立可聚焦的详情按钮，并控制行内动作冒泡。

## 7. 边界与验收

插件主页业务能力不进入导航、命令菜单和首页快捷区；“打开插件”只用于启动独立 UI。
全局故障、身份不可用、等待用户确认的任务不能藏在页内菜单或未打开的详情里。

验收覆盖 390、768、1024、1280、1904px，中英文、200% 缩放、长名称；长列表和长详情分别滚动时侧栏/头部保持正确。
Native 标题栏、拖拽区和系统窗口按钮另做真实 WebView 验证；Folo 的 Electron 标题栏样式不能直接复制给 Tauri。
