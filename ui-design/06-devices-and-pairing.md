# 06 · 设备与配对

> ✅ **本文已按 ADR-025 重写**（2026-11-01）。传输是明文 TCP，没有证书、私钥、令牌、验证码，
> 也没有「接受对方请求」这一步。要了解为什么，读 [ADR-025](../20-adr.md#adr-025--mvp-不带传输加密与设备身份)。

> 🟡 页面候选方案。设备可采用面板、卡片或简洁行；下文以行说明信息与动作，不把列表当作目标。

## 1. 这个页面负责什么

设备页负责**发现**、**列表**、**忘记**。它不提供发送文字/文件、远程剪贴板等业务入口——
那些入口在各自的页面里，选中设备即可发起。

```text
设备                                     [扫描]

已配对
  Pixel 8             Android     在线            [更多]
  Work PC             Windows     离线            [更多]

附近设备
  unknown-android     Android     未配对          [更多]
```

| 位置 | 默认字段 | 详情字段 | 操作 |
| --- | --- | --- | --- |
| 已配对行 | 名称、平台、在线/离线、阻止状态（若有） | ID、地址（若有）、最后发现时间 | 查看详情、忘记 |
| 附近设备行 | 名称、平台、未配对 | `address`（若有）、完整 ID、发现时间 | 查看详情 |
| 页头 | 标题、扫描状态/动作 | 扫描进度展开后可看时长/数量 | 扫描、扫描中取消 |

**附近设备行没有「配对」按钮。** 见下一节。

`paired` 与 `online` 是两种事实：**「在线」只说明这台设备现在能连上**，不代表它是谁；
「离线」不等于关系失效。`blocked` 若为真必须有明确摘要，详情里的操作以实际契约为准。

## 2. 「配对」在这里是什么

**连上、报上名字、记下来。** 没有第一步以外的步骤：

1. 用户在需要设备的地方（例如发送文件时）选中一台设备。
2. 内核拨过去，握手交换 `device_id` / 名称 / 平台 / 能力位。
3. 握手完成即写入 `paired_devices`，**两侧都写**。

此后这台设备出现在「已配对」里，仅此而已。没有要抄的码，没有要点「接受」的请求，
没有需要人搬运的证书，也没有「等待对方确认」的中间状态。

**为什么附近设备行没有按钮**：拨号要有东西可送。一个只为让屏幕显示「已连接」而建立的连接，
既没有用户目的，也没有可观察结果。设备页因此只做发现与记录，不做建链。

**为什么两侧都写**：若只有拨号方记录，同一条链路会在两台屏幕上显示成「已配对 / 未配对」，
而「忘记」会在其中一侧指向一行根本不存在的东西。

## 3. 扫描反馈

未扫描时不放进度区；扫描中把按钮换成「停止扫描」，用紧凑进度和已发现数量。
elapsed/total、scanId 放折叠详情，不在默认列表上方摆三列技术指标。

扫描结束保留已有结果，短反馈说明找到多少；没有发现时提示检查是否同一网络并提供重试，
**不宣称网络已排障成功**。扫描失败就在列表头部给原因和重试；旧结果若仍显示，
标明是已知结果，不伪装成本次扫描的结果。

取消请求被接受不等于发现窗口已经退出；在内核确认结束前保持等待。

## 4. 忘记

从已配对设备更多菜单末尾进入。确认框写明目标与忘记后的影响：

- 对方会回到「附近设备」；
- 下次连接按**首次连接**处理，会重新记录一次；
- 这台设备上关于**自动接收**它的偏好一并撤销。

**「忘记」不阻止对方再来。** 每次握手都会重新写一次记录，所以忘记只删掉本机这一行。
要真正拉黑需要一张独立黑名单表 —— **这是 MVP 之外的能力，当前没有，界面不得暗示它有。**

## 5. 文案边界

- 不出现「已验证」「可信」「加密」「证书」「指纹」这类词：这些性质**不存在**，写出来就是假的。
- ID 与地址只用于**辨认**，不用于声称身份；同名设备必须能靠完整 ID 区分。
- 「发现」不等于可信：可以说「通过局域网发现找到」，不得延伸为「这是谁」。
- 页面上不需要任何「保管凭证」类的提醒 —— 没有凭证需要保管。

## 6. 验收

列表侧：无设备、只有已配对、只有附近设备、混合列表、同名设备、长 ID；
扫描中/结束/取消/失败。

关系侧：

- 一次成功发送之后，**两侧**列表都出现该设备（不是只有发起方）。
- 忘记之后该设备回到附近设备；再次发送时按首次连接记录，列表重新出现它。
- 不阻止：被忘记的设备再次连上时不报错，只是重新出现。

真实双设备握手需 Native 验证；纯浏览器假内核只能证明界面流程与调用参数。
