# 07 · 插件管理

> 🟡 页面候选方案。列表、卡片和详情容器按真实管理任务选择；重点是页面组织与完整操作体验，不要求照搬 Folo。目标以 [00](./00-product-quality-bar.md) 为准。

## 1. 首先拆开三种任务

**已安装**回答“我的插件能否运行、怎么管理”；**发现**回答“有哪些可安装”；**安装流程**处理这一次来源与确认。
保留一个“插件”一级入口，默认已安装，页内用 Tabs/Segmented 切分类；页头“安装插件”打开流程。
现有三个输入区域不再同时常驻：已安装筛选只在已安装，注册表搜索只在发现，本地路径只在安装流程。

发布者列表属于信任管理，放页内“发布者管理”入口，不在每次浏览插件后面追加一长段说明。
发布者变更或待决策的信任问题仍需在对应对象上可见，不能因移动管理位置而隐藏风险。

## 2. 默认已安装视图（列表方案示例）

```text
插件                                   [安装插件]
[已安装] [发现]                         [更多]
筛选已安装的插件

Starter                  运行中     [开关] [打开] [⋯]
  插件提供的短描述（至多一行，可选）

Touchpad                 已停用     [开关]        [⋯]

Shortcuts                已停止     [处理]       [⋯]
  多次请求被拒绝，需要处理权限
```

对象可能没有 UI，不强制每行同样有打开按钮。示例名称只作结构展示，不新增宿主内业务。

| 信息 | 默认行 | 详情 |
| --- | --- | --- |
| 名称 | 必须可辨认 | 完整名称，插件 ID |
| 描述 | 可选一行次级，不由宿主自动翻译插件内容 | 完整描述 |
| 状态 | 一个可信运行状态 | 状态原因、健康/配额详情 |
| 版本/发布者 | 需要辨认时可做次级短摘要，不全部字段名展开 | 完整版本、发布者、信任/指纹 |
| 更新 | 有更新时短摘要，新增权限必须显式指出 | 版本差异、权限变化、检查时间 |
| 权限 | 待处理时显示摘要/入口 | requested/granted/denied 的完整状态和决策 |
| 调用审计 | 不常驻列表 | 审计分类，按需分页读取 |
| 配额 | 正常不占位，异常短摘要 | usage/limits/计数 |
| 操作 | 启用开关、可用的打开、更多、异常处理 | 同步、更新、重试、移除等完整入口 |

只有真实有新决策时显示“需要授权”；不能把 `requested.length > 0` 当成始终需要再授权。
权限是否已决、哪些变化需要再确认，以内核的状态与权限语义为准；不能用粗糙集合运算替代带范围的能力判定。

## 3. 插件详情

建议包含“概览 / 权限 / 调用记录”，更新与运行异常在概览就有摘要；元数据和配额可用 Collapse。
少量信息可就地展开；内容较长时选择 `ADrawer` 或独立页，需要连续对照时才在 ≥1280px 且符合空间预算时并排。覆盖式详情在窄屏全宽，关闭后回到原摘要位置与焦点；就地展开不额外创建模态层。

详情标题有名称、状态、关闭；主操作为“打开”（有 UI 且允许时），管理动作用更多。
启用、重试、打开窗口是三种行为；状态不足时给明确原因，不能“开关显示已启用”就宣称运行正常。
`?plugin=<id>` 通知链接直接打开此详情；不存在则说明未找到并保留返回列表，不能空白。

## 4. 行菜单的固定分组

| 顺序 | 动作 | 规则 |
| --- | --- | --- |
| 1 | 查看详情 / 权限 / 调用记录 | 导航到同一对象对应分类 |
| 2 | 检查更新 / 同步到设备 | 显式执行，不因 hover 菜单预先执行 |
| 3 | 更新 / 重试 | 只在真实可用状态出现；新增权限进入确认流程 |
| 4 | 移除插件 | 分隔线后危险动作；打开现有数据保留确认 |

右键菜单与更多共用动作定义；键盘/触摸都可使用更多。主操作、菜单与详情不得各写一套调用参数和授权判断。
busy 绑定 pluginId 与动作，不能检查一个插件时禁用全部列表，也不能同时发两个互斥的更新/移除请求。

## 5. 安装流程

### 5.1 来源清楚，输入按需

点击“安装插件”后显式选择“本地目录/插件包”或“注册表”；不根据字符串是否有斜杠猜来源。
本地支持原有目录选择、插件包选择与手动路径；注册表支持准确的插件 ID 与预览。
注册表未配置时原位说明并链接设置“插件与来源”，本地安装仍可用。
表单源切换时可保存各自草稿，但待确认结果必须绑定来源与请求版本，旧预览不能用于新输入安装。

### 5.2 不把“预览”说成“已验证”

注册表预览展示名称、版本、发布者声明、能力清单、UI/headless、可用的大小信息；实际签名在下载字节后验证。
保留这个边界，不能在预览尚未验签时画可信勾选。完整能力清单放滚动正文，新增/敏感权限不能只在 hover 出现。
本地路径若没有独立预览 API，不能声称已核验能力；沿用真实安装后状态和授权步骤，并按需要另定义统一预览契约。

Starter 源码目录缺少 `ui.zip` 等构建产物时，在输入/结果处明确提示完整插件目录或插件包要求；不能自动运行外部项目构建，也不把源码根目录悄悄改为 dist。

### 5.3 安装与授权保持分离

安装成功不等于自动运行/授予全部权限；以返回的 enabled、权限和信任状态决定下一步，不能顺带信任发布者。
成功反馈提供“查看插件”，必要时直达权限页；不以每个步骤都弹成功对话框打断流程。
失败保留输入、来源与可执行错误，不用通用 That did not work 替代已知原因。

## 6. 权限管理

先展示当前结果：已授予、已拒绝、尚需处理。完整能力名和范围可复制；为常见能力提供本地化说明，但不更改能力标识。
需要用户决策时显示可勾选项与明确“允许所选权限”，既有值回填应反映当前有效决定；新增项不能默认全选。
没有变化时不显示一个永远可点的重复授权大按钮；允许后等待真实结果更新。
拒绝的可选能力不必把整个插件染红；是否阻止运行由内核报告。错误原因与权限请求要区分，不能把所有异常归为缺权限。

## 7. 更新与发布者

普通有更新用小标记/短文字，不用每个插件一块大 warning。新增权限、发布者变化、签名失败则需要清楚的可见说明。
检查更新不会自动更新；自动策略继续由内核已有规则决定，前端不能为“少点击”绕过新增权限或发布者检查。
完整更新时间和旧/新版本在详情；列表仅显示需要决定的信息。

发布者管理中显示 publisherId、指纹、信任状态与显式动作；指纹可换行/复制，不只显示不可核对的前后几个字符。
允许一次安装与信任未来版本不是同一个决定，必须保留各自含义。取消/撤销的影响也在对应确认中说明。

## 8. 同步、审计与移除

**同步**：打开才读取计划，展示目标设备在线/版本/是否需要产物等真实信息；保留失败列表和部分成功，不能只用绿色“已同步”。
目标设备有无产物不代表已授予运行权限，不在同步流程中默默扩权。

**审计**：进入调用记录分类才读 `plugins_audit`，沿用20条分页与服务器顺序；关闭详情后停止相关读取。
当前对象、offset、请求序号绑定；快速切插件时旧响应不能覆盖新对象。拒绝原因、trace、耗时、精确时间在记录详情完整可达。
清除记录是独立危险动作，先说明影响；不为列表整洁自动清审计。

**移除**：继续保留默认“保留数据”，删除数据选项每次打开都不勾选；显示数据路径、实际回收量/残留结果。
移除前按对象阻止重复操作，失败仍可定位该插件；界面不能因为先删行就吞掉残留清理错误。

## 9. 搜索与发现

已安装筛选可本地实时匹配标题/ID；发现搜索按当前命令语义提交，防抖或 Enter 二者明确，不在每个按键无节制请求。
输入法组合态不提交；快速更换词/排序的旧结果不得盖住新结果。分页期间保留已有结果并给独立 busy。
无匹配与列表加载失败、没有注册表配置是三种状态；不要都画“暂无插件”。
不要在本轮引入本地索引引擎或新的插件市场后端。

## 10. 验收

0/1/20/大量插件、无 UI/有 UI、运行中/停用/异常/待授权、旧值与新增权限、正常更新/新增权限/发布者问题、部分同步失败。
目录/包/注册表各走一遍，确认取消不修改权限，移除默认保留数据；菜单、行内开关与详情不会触发两次动作。
中英文长名称/ID/权限范围、390px/1024px/宽屏、键盘与触摸可完成同等管理路径。
