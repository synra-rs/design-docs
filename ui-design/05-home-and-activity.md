# 05 · 首页与活动

## 1. 首页回答什么

**我需要处理什么、什么还在进行、当前有哪些可查看的结果。**
保留导航名“首页”，页内“已接收”任务区建议改称“任务”，避免把通用调用当作文件收件箱。
不加入分享剪贴板、发送文字/文件、插件业务快捷按钮，也不因示例出现 GitHub 就加入 GitHub 功能。

## 2. 目标首屏

```text
首页                                  [刷新（需要时）]
此设备 ── Pixel 8    已连接             [管理设备]

待处理  1
  来自某设备的请求     等待选择/确认     [处理] [拒绝]

进行中  1
  Pixel 8  文件名     接收中  42%        [取消]

任务
  已完成  @synra-plugin/github           [详情] [更多]

接收记录
  文件名  大小  接收时间                 [详情]
```

这是包含相应数据时的示意。没有待处理就不画空的“待处理”大区；没有进行中只显示短状态行或省略该组。
不使用虚构数量、时间和结果填满布局。现有示例插件 ID/trace 可保留在假内核环境，用于证明展示能力。

## 3. 内容分层

| 区域 | 默认 | 点击后 | 空状态 |
| --- | --- | --- | --- |
| 连接摘要 | 本机→对端短线、名称、一个状态 | 管理设备 | 无配对时提供唯一的“配对设备”引导 |
| 待处理 | 请求来源、等待原因、操作 | 当前请求完整说明/候选 | 没有就不占一个大区域 |
| 进行中传输 | 对端、文件名/种类、方向、进度、取消 | 完整 ID、字节数、原因 | 一句“暂无进行中的传输”，不再配插图与重复管理按钮 |
| 任务 | 状态、插件标识或已知标题、必要异常/重试摘要 | trace、开始时间、候选、错误详情 | 一句“暂无任务”，不能假装存在历史 |
| 接收记录 | 文件名、大小、接收时间 | 完整路径等元数据 | 一句“暂无接收记录” |

“已连接”和“设备已就绪”不重复常显；正常状态保留一个即可。
保留“设备之间一条线”的识别元素，但缩成摘要，基底用普通面；浮起材质只用于真正的弹层。
多个对端时显示真实可达数量或有意义的当前对端；传输时从 `peerDevice` 定位对端，不能随便拿第一台在线设备。

## 4. 通用任务决策不能藏起来

待选择设备、待确认、拒绝与错误恢复有真实时间约束，不能只放在详情、hover 或 Toast。
候选列表按 `IntentCandidate` 展示实际 title/设备，不推断插件业务内容；候选离线时明确禁用/解释。
每个 intent 的“处理/拒绝”按对象独立 busy；调用失败保留该任务与草稿，不以关闭详情代表用户拒绝。
重试次数和 `gaveUp` 区分：重试停止不等于远端动作确认失败，保持现有内核语义。

全局接收确认与首页同一任务只能执行同一个决策，不生成两个互相竞争的本地状态。具体全局提示见 [08](./08-settings-and-system-surfaces.md)。

## 5. ID、时间与接收文件

主列表可保留 `@synra-plugin/github`；长标识允许换行或截断后在详情完整展示。
`01HQ00000000000000000TRACE1` 不必永远展开整行，但必须能在详情完整读取与复制；复制只复制实际值，不包含“调用记录”标签。
若没有可解析的插件标题，直接使用 ID，不凭命名空间自动生成业务名称。

时间字段已经存在：`IntentSnapshot.startedAtMs`、`TransferSnapshot.startedAtMs`、`ReceivedFile.receivedAtMs`。
开始时间不能被标成完成时间；未知时间不展示“刚刚”。相对时间可用于列表，精确本地时间在 hover/focus/详情提供。
接收文件仍是**只读记录**：文件名、路径、大小、接收时间；不恢复打开、显示目录、删除按钮。

## 6. 数据能力与阶段边界

核对来源：`src/pages/HomePage.vue`、`src/stores/intents.ts`、`src/ipc/command-inventory.ts`，以及 `@synra/protocol/generated/ui.ts`。

| 数据 | 当前来源 | 当前能做 | 不能假定 |
| --- | --- | --- | --- |
| 当前任务 | `intent_list`＋事件 | 当前状态与决策 | 持久完成历史、完成时间、结果正文 |
| 在途传输 | `transfer_list`＋事件 | 方向/进度/取消 | 结束后还能从该列表查到 |
| 接收文件 | `transfer_received`＋接收通知刷新 | 文件元数据列表 | 所属插件/trace/对端一定可关联 |
| 插件调用审计 | 对象级 `plugins_audit` | 某插件的调用记录 | 全局任务结果等价于能力调用审计 |

当前 store 收到 `intentFinished` / `transferFinished` 会移除对应行；假内核能显示“已完成”不证明 Native 有持久历史 API。
首批只重排已有当前任务和接收文件，不把两者用文件名、时间邻近或显示名称强行关联。

若后续确实需要“最近活动”统一时间线，先定义终态记录、稳定事件/记录 ID、发生/完成时间、查询分页、保留与清理、跨来源关联及脱敏边界，修改协议真相源再生成类型。
不能在页面本地缓存一份“看起来完成了”的历史冒充内核持久状态，也不新增旧格式兼容层。

## 7. 排序、加载与更新

待处理固定在前；当前运行项不因每个进度事件跳来跳去。初始排序用可靠字段，同组更新保持稳定位置。
接收记录沿用来源顺序或可靠 `receivedAtMs`；相同时间用稳定键处理，不用数组索引当身份。
数据未读到用静态骨架；读失败给对应区错误，不先显示“没有任务”。不要为了首页新样式重新订阅全局事件。
完成后的真实移除、取消中、错误恢复都应由 store/快照更新；前端不在点击时抢先删行。

## 8. 验收场景

- 无配对、无任务：一个清楚引导，没有三张重复空插图。
- 已配对、无任务：短连接摘要与紧凑空状态，手机首屏不被占满。
- 1/多待处理、1/多传输：决策与取消常显，焦点和正在阅读的行不跳动。
- 完成事件：按真实当前数据能力更新，不凭演示渲染假历史。
- 接收文件、长路径/ID、中英文：值完整可达，主区域不横向溢出。
- 请求拒绝/超时/IPC 失败：保留恢复入口，不让关闭提示等价于拒绝。
