# 08 · 设置与系统界面

> 🟡 页面候选方案。先保证 [00](./00-product-quality-bar.md) 要求的整体完成度；设置较少时可保持直接分组，分类导航仅在能改善查找路径时采用。

## 1. 设置按用户目的分类

不把“高级”当作所有罕用功能的唯一收纳箱。保留设置页面与已有配置来源，分类先用现有 Menu/Tabs/Select 实现。
默认进入“通用”，切分类不重建应用事件订阅；身份异常在任何分类都有可见摘要和“处理”入口。

| 分类 | 放入的现有内容 | 默认内容 | 按需内容 |
| --- | --- | --- | --- |
| 通用 | 语言、设备名称、登录时启动、取消传输前确认、接收通知 | 常用偏好与值 | 名称编辑、平台不支持原因 |
| 设备与安全 | 设备身份、自动接收设备列表、身份修复/清理 | 身份正常摘要、自动接收状态 | 指纹、后备登记、运行时状态、退休密钥数量、修复确认 |
| 插件与来源 | 注册表/镜像、插件更新策略、调用历史保留天数 | 当前值和可编辑控件 | 技术来源格式说明、镜像顺序说明 |
| 诊断 | 性能、环境检查、日志、崩溃记录、诊断导出 | 分组入口/必要异常摘要 | 指标读取与轮询、详细探测、日志、导出选项 |
| 关于 | 平台、应用/内核版本、设备 ID、当前外观说明 | 真实可用元数据 | 完整标识复制；不增加更新/发版功能 |

这是推荐的信息归属，不是新建配置键清单。现有 config key、默认值、验证规则、Native 能力保持原语义。
只有一种深色外观时，不画空的主题选择器；“深色外观”可在关于简短记录。
设备名称仍从同一 identity/store 更新侧栏，不能设置页改了而壳层显示旧值。

## 2. 分类导航与设置行

宽屏用页内窄分类导航＋设置正文；窄屏使用具名分类 Select/紧凑导航，一次只显示一个分类。
不要为五个设置分类再开一整条应用级侧栏；其层级必须明显低于首页/设备/插件/设置。

设置行结构：**标签和必要短说明在左，值/控件在右**；空间不足改为上下排列。
说明分三种：标签已经足够表达的省略；不常用解释放帮助；安全影响/禁用原因留在操作处常显。
输入不是只靠 placeholder 命名；Switch 的 label 与控件有可访问关联，不依赖视觉上的相邻文本。

## 3. 保存、草稿与冲突

| 控件类型 | 推荐交互 | 失败后 |
| --- | --- | --- |
| 语言、单一开关、明确策略 Select | 保留现有即时保存，显示局部 busy | 回显真实值，原位错误，可重试 |
| 名称、注册表/镜像、多字段输入、保留天数 | 显式保存/取消，保留草稿 | 输入不丢，错误标到字段/分组 |
| 身份修复/删除类操作 | 明确确认后执行，说明影响 | 当前身份与错误保持可见 |

切分类时有未保存草稿：暂存在当前会话并显示未保存状态；真正离开设置时提供保存/放弃选择，不能静默丢失或偷偷提交。
外部配置事件到达时更新非编辑项；正在编辑的字段若冲突，说明当前值已变，让用户重载或明确覆盖，不把旧读取响应覆盖新草稿。
已有 settings store 的异步读取版本保护必须保留。

切换语言即时更新当前分类、菜单、对话框、组件库与 Native 文案；不重置选中对象、输入和滚动。
插件标题/描述属于插件内容，不由宿主擅自改写；没有翻译时显示原文。

## 4. 设备身份与自动接收

正常状态默认一条“设备身份正常”摘要，指纹与细项按需查看。
恢复登记、运行时不可用、重启要求和清理残留不能只藏在“设备与安全”未选中的分类里：设置页头部显示一次摘要，点击定位详细区域；进入该区域自动展开。
同一警告不在页头和详情重复两整段，页头给影响，详情给数据和恢复操作。

修复身份确认继续绑定当前完整指纹，防止点击后目标变化；busy 期间按实际能力禁止中断或重复执行。
自动接收列表始终能查到真实允许的设备，设备名称无法解析时用 ID；移除单个允许项不能等价为取消配对。
“总是允许该设备”默认不勾选，每个新请求重新开始，不能因 UI 收纳变成默认授权。

## 5. 插件与来源

注册表按真实顺序展示，显式保存；技术格式如 `static:` 可放帮助和校验错误，普通用户不必每次看教程。
来源为空时表示关闭注册表安装，不能 UI 自动填默认公网地址。来源不可用时本地安装仍是有效路径。
从插件安装页跳来可定位“注册表”，回去保留原安装来源/输入；不自动保存未提交的来源。

更新策略需要一句真实影响说明，尤其涉及自动安装的策略，不能把风险说明只放 hover。
调用历史保留天数保存后的生效方式按内核返回说明；若需重启，保持明确提示，不假装立即应用。

## 6. 诊断与性能

诊断页仍分为性能、环境检查、崩溃、最近日志、导出，各组有独立加载/失败状态，不以一个共享 error 覆盖整页。
性能**仅在诊断分类且性能区域打开、页面可见时**读取/轮询；离开分类、折叠、卸载或窗口不可见时停止，恢复后按需要读取一次。
这是对当前“展开整个高级设置就轮询”的进一步收紧，实施时要迁移生命周期，不能保留旧 timer 再加新 timer。
指标不支持与指标为空分开；有数据时带快照时间/陈旧提示，不能让旧数据冒充实时。

环境检查只在显式运行时执行；默认先看异常/需处理项，查看全部可展开，不自动重复昂贵探测。
日志按点击读取、受条数/字节预算约束；不为了填满界面常驻日志流。
崩溃恢复说明保留实际“清除后是否恢复正常启动”的影响；清除不能被伪装成无影响的收起操作。
诊断导出选项中涉及调用记录、调试日志的说明保留在确认处，默认不因上一次选择自动扩大内容；结果显示实际 included/excluded 与落盘路径。
导出是写本地文件，不默认上传到任何服务，不能用一个“发送报告”按钮替代。

## 7. 全局通知、异常与待处理

| 类型 | 默认呈现 | 生命周期 | 操作 |
| --- | --- | --- | --- |
| 安装/更新成功、复制成功 | 短反馈，避免压住正文 | 可关闭/合理短暂显示 | 有目标时“查看插件”直达详情 |
| 全局网络受限 | 壳层紧凑状态条，一次说明影响 | 条件解除才消失 | 合理的详情/重试，不每页复制 |
| 插件异常 | 列表短摘要＋详情 | 原因解除才消失 | 处理权限/重试等真实建议 |
| 身份/启动恢复异常 | 全局或设置可见摘要 | 不能仅靠 dismiss 当作已修复 | 定位设备与安全/诊断 |
| 等待接受/拒绝的传输 | 清楚的全局任务提示 | 不自动消失、不随换页丢失 | 接受/拒绝，默认不记住允许 |
| 局部操作失败 | 对应按钮/区域附近 | 修复或明确关闭 | `actions` 恢复入口＋详细错误 |

全局待处理提示在手机不能固定宽320px再加两侧偏移造成溢出，应受视口、安全区与软键盘约束。
多个请求排队时显示数量与当前对象，切换请求重新清空“始终允许”，不让前一个对象的选项污染后一个。
`transfer_respond` 失败保留请求、选择和局部错误；接受/拒绝始终绑定当前 transferId，单个在途回应阻止重复操作，切换对象后旧回应不污染新请求。
命令成功只说明回应已送达，不由界面提前删除权威记录；等待事件推进时显示已回应，并提供只读“检查状态”，读取失败不自动重发接受/拒绝。
手动读取沿用共享 store，旧读取不能恢复已由新事件结束的请求，也不能覆盖更晚的读取；不新增全局订阅或轮询。
队列推进时仅在焦点原本位于提示内才交接焦点，正常到达不抢焦点；礼貌公告只包含当前请求摘要，技术信息按需展开。

以上前端行为已在应用 `67d9868` 实现，截图和测试边界见[第八批记录](../history/2026-10-29-transfer-prompt.md)。Native 的记住偏好仍先于回应有效性检查，且持久化失败被忽略；需要单独修正原子归属、失败语义与配置通知，不能把前端通过记为真实接收/持久化链路已完成。

已有 NoticeHost 通知指向插件 query 的行为要保留，改版后真正打开目标详情，不只把插件页滚到顶。
错误不再一律用模糊提示；开发技术详情可折叠，用户可采取的动作与原因常显。

## 8. 托盘与独立插件窗口

托盘保留“显示窗口 / 退出”，语言跟随已有设置。不借本次设计加入插件业务菜单或新的后台操作列表。
关闭主窗口与退出进程是两种行为，文案与实际后台任务生命周期一致；Native 无托盘平台仍可使用窗口。

插件详情“打开”指向独立 WebView；打开中显示 busy，失败留可理解的原因，已有窗口应聚焦原窗口。
权限确认属于宿主，插件自己的页面内容/操作属于插件；宿主不为所谓统一 UI 嵌入第三方 HTML，也不让插件控制主程序首页位置。
插件文案与本地化由插件自己负责，宿主提供的 `env.locale` 不代表能自动翻译插件 UI。

## 9. 验收

按分类找到语言/名称/自启动/自动接收/注册表/更新策略/保留天数/诊断全部现有项，不能收纳后丢入口。
验证即时保存失败、草稿保留、外部事件冲突、身份异常自动定位、指标关闭无轮询、日志不常驻、手机软键盘和通知队列。
托盘、原生文件通知、自启动可用性、独立窗口聚焦需实际 Native 验证；浏览器预览的 unsupported 是能力限制，不当作 Native 结论。
