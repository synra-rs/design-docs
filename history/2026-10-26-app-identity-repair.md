# 应用身份修复交互（2026-10-26）

承接[显式身份修复](./2026-10-26-identity-repair.md)，在设置页连接查询、修复和清理。
当前契约见 [08 §2.2](../08-ipc-and-frontend.md)、[17 §5](../17-storage-and-config.md)，完整任务见 [19 §0.2](../19-roadmap.md)。

## 共享流程与数据

协议层新增 CredentialEnrollment、CredentialSnapshot、CredentialCleanupReport 和 CredentialRepairReport，
应用与 daemon 使用相同的 core 维护函数、状态判定与错误分类，宿主仅做参数适配和序列化。
旧的 previousPairingsRevoked 常量字段已移除；换钥成功本身要求此前授权在事务中撤销，不保留旧输出兼容分支。
cleanup 以可空 remaining、errorCode、detail 分别报告数量或失败，不能把清理失败报告为换钥失败。

状态区分持久登记就绪与当前进程是否捕获同一证书，旧上下文不能因数据库出现新登记就被宣称可用。
ready 是此前读回提交的事实，不是当前原生后端的健康探测；缺钥导致启动失败时仍可明确修复。
一条 SQLite 查询同时读取本机 id、公开登记和待清理数量，避免持有单连接互斥锁仍可能被另一连接换钥而产生混合快照。
Host 锁仅覆盖公开指纹的复制，数据库查询和原生密钥 IO 均在释放它之后执行。

## 界面与错误路径

设置页显示指纹、密钥存储、保存状态、当前身份、待清理数量和重启说明。
确认框捕获打开时的指纹，后台刷新不替换用户已经审阅的目标；失效确认由共享服务拒绝。
成功或失败都会重读身份与设备列表，因为原生写入失败前也可能已撤销配对和改变公开登记。
查询串行合并并丢弃被新命令失效的响应；命令错误、状态读取错误和设备列表读取错误分别保留。
设备列表刷新失败可独立重试，不重复修复命令；新钥提交与清理失败同时可见，清理重试不会抹掉修复结果。
store 保留本进程的操作结果以支持导航，重新打开页面会读取后端状态；完整应用重启后以新上下文重新读取。
预览假内核仅返回没有登记的状态，拒绝伪造原生身份修复。

## 原生入口边界

检查本地 Tauri 2.12.4 的分发实现后确认，不能将 main 窗口的插件权限配置等同于本应用命令的 Host 隔离。
原先共享注册表只表达接口契约，没有在 Tauri invoke 分发前执行它。
本轮将该注册表接入统一原生入口，以实际 WebView 的 label 选择接口；
非 main WebView 不能调用身份维护或任何其他 Host 命令，只能进入随后仍需 token 与权限校验的插件桥接。
未知命令默认拒绝，调用方参数不能伪造实际窗口身份。
测试枚举全部 Host 命令验证非主窗口拒绝，并检查插件桥接及未知命令。
默认 Tauri 编译验证这段路由实际接入生产 handler；未声称完成真实 WebView 平台运行矩阵。

## 验证

应用生产命令使用真实文件数据库、随机测试身份及 Windows 原生密钥后端，
验证失效指纹拒绝、修复后元数据撤销、新登记就绪而当前进程仍需重启，以及独立清理。
存储并发测试使用两个真实连接连续换钥，核对读取的证书代次和清理数量始终一致。
协议测试检查显式 null 和未知字段拒绝；JS 守卫核对字段类型及可空性，发现省略 null、可选键、
错误布尔类型和字段级序列化改动，不能把未支持的属性当成一致。
组件测试验证确认前无写入、失效指纹拒绝并重新审阅后成功、缺钥启动状态仍可修复、取消、
重启提示及清理失败重试；store 验证旧读取竞争、失败后撤销复核和设备列表读取失败后的独立恢复。

阶段门禁通过：core 808、store 276、protocol 244、IPC 123、daemon 256 项单测，
以及 API 守卫、相关集成测试和 doctest；受影响五个包全部目标 Clippy 通过。

按影响复用结果覆盖当前 344 项；类型检查、生产构建、全量 lint（修正设置页导入顺序后定向复核）和 8 项形状守卫通过。
