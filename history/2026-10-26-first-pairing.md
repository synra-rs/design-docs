# 生产首次配对入口（2026-10-26）

本轮将已有受限 TLS、用户同意及持久绑定机制接入共享任务服务和 CLI/daemon 的生产命令，
承接[宿主认证接入](./2026-10-26-host-authentication.md)中明确的首次配对缺口。
当前契约见 [04 §7–8](../04-wire-protocol.md)，完整实施范围仍以 [19 §0.2](../19-roadmap.md) 为准。

## 流程与状态

A 导出公开证书邀请；B 经可信带外路径取得并明确导入后，开启只接受 A 证书的临时受限监听，
返回含本机证书及临时端口的应答；A 再经可信带外路径导入应答，双方进入同一受限 mTLS 机制。
导入必须同时匹配用户所选设备的 id，发现地址和临时端口均不能替代证书认证。
没有新增密码学握手或自制短码；同意与持久回执继续使用原有 TLS exporter 绑定。

`PairingService` 由已初始化的网络身份共享，profile 更新和两个 Host 的克隆保留同一任务槽位。
其运行时快照仅描述任务进度，不从快照产生授权；最多一个活动 worker 和一个保留终态，
取消中的 worker 真正退出前仍占用槽位。任务 id 同时用作持久授权代次，便于关联状态与撤销。
CLI 的旧 `pair DEVICE` 和控制通道的 token 应答入口已整体替换，无旧格式回退。

SQLite schema 20 重建非授权性的配对任务日志，保留独立的既有凭据授权表。
新的预留阶段 binding 为 NULL，明确尚无 TLS 绑定；握手成功后只能推进同一预留代次。
取消和解除配对都覆盖握手前预留，撤销后晚到连接不能重新领取任务。
双方持久回执后，本机授权与设备列表记录在一个事务中提交；列表写入失败也回滚授权。
列表名称和路由仍为发现元数据，空 token 不具备任何认证能力。

取消先持久阻止原代次提交，再通知底层 IO；Windows 上的 socket 副本 shutdown 不能稳定提前结束阻塞读取，
因此受限连接使用原子取消信号和有界 IO 轮询，保留 TLS 实例与总预算，普通业务连接不增加轮询。
数据库锁等待后和最终事务提交前均检查单调时钟预算，避免旧时间采样在等待后仍放行提交。

## 验证与适用范围

共享服务测试使用真实 TCP、TLS 与独立文件数据库，不预置对端授权；
验证两次明确导入后生成持久授权并建立真实业务连接、错误证书拒绝、监听过期、静默 TLS 取消、
任务槽位及旧 id 隔离，以及 TLS 开始前撤销使晚到连接失败。
daemon 测试通过生产 Kernel 命令验证首次配对与文件重开后的授权、取消、错误邀请身份和不存在的任务；
控制通道验证所有动作必须先完成本地握手，CLI 验证新命令和参数到控制请求的映射。
存储测试注入设备列表写入失败，确认任务阶段与授权一并回滚，并覆盖已到期的单调提交预算。

阶段门禁通过：工作区测试、集成测试和 doctest、工作区全部目标 Clippy、修改文件格式检查、
12 项架构守卫（含 Rust 1.88、应用调用方及 95 份文档链接），应用默认 Tauri 编译及全部目标 Clippy，
Android 核心交叉编译；核心库 801 个单测、daemon 255 个单测和存储库 271 个单测通过。
首次全量在新增枚举的 API 规则处中止，补齐该枚举约定后定向复核守卫，再继续其余包，
已通过的 api-guard 单测未重跑，并补齐其尚未运行的 doctest。

应用全量回归中 321 项通过，一项托管上传清理测试暴露既有竞态：传输行先移除、上传目录后清理，
观察者可能看到任务结束而缓存仍存在。修复后由注册表保留任务拥有的文件及目录，
在移除行和发布完成事件前清理，进度更新保留清理归属，取消和 worker 启动失败复用同一结束路径。
清理只作用于明确归属任务的文件及非递归目录，不删除用户选取的源文件。
保留原失败测试的断言，定向复核传输模块 33 项与插件桥接 52 项均通过，其余应用结果按影响复用；
没有为等待后台清理而放宽测试条件或增加固定 sleep。

## 后续范围

应用界面的带外邀请导入与应答展示尚未接入；旧六位码流程不能为未批准身份生成业务授权。
Android 原生密钥后端及设备运行验证、显式身份修复和平台恢复仍未完成，D1 保持开发中。
重启不恢复运行时 socket 或任务快照，未完成预留在到期或显式撤销前继续阻止新任务占位，不能自动晋升授权。
双方最终提交仍非跨设备原子事务；失败侧不得从残留日志自动补发授权，沿用[持久绑定记录](./2026-10-26-peer-trust.md)中的限制。
本轮未做前端改动、性能基准或发版工作，测试夹具不证明原生私钥后端的持久性。
