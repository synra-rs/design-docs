# 网络函数的范围授权

日期：2026-10-26；对应 [10 §2.5](../10-capability-and-sandbox.md)、[M2](../19-roadmap.md) 与 [验证策略](../21-testing-strategy.md)。

## 缺口与修复

函数族模式直接作为查询目标，导致具体域名授权在导入与调用时被拒；新增负例先复现失败。
第二个回归测试复现了限定域名后的通配符被移到前缀、授权顺序发生变化的问题。
解析器现保持原顺序，导入只判断 fetch 家族可用性，调用则用实际 URL 与方法作具体目标检查。
真实 CLI 回归还发现 manifest 忽略方法范围：限定 GET 的声明被误拒，而较宽权限可能被窄声明掩盖。
现对具体域名及方法做双向一致性检查，覆盖合法 GET、多方法、缺少权限及声明外方法的拒绝。

HostCalls 与 synra-fetch 共用 URI、方法和 capability 授权规则，后者在每跳 DNS 与 IO 前重新检查。
应用与 daemon 共用完整 JSON 请求入口，从数据库读取当前授权；方法权限不留在客户端缓存中。
能力拒绝保留统一错误码与拒绝审计，非法参数不产生宿主效果，损坏的持久授权整体拒绝。

## 验证证据

定向测试覆盖实际 CLI 组件声明、实际 WIT 编码的 Wasm 调用、越界目标、用户信息伪装、
大小写及尾点域名、方法变化、JSON 转义、非法参数，以及两个宿主的 SQLite 授权变更。
真实 TCP 服务验证重定向每跳的方法权限，并断言被拒目标没有收到请求；同一客户端的撤销后新调用被拒。

阶段验证：core workspace 3581 项测试通过，零失败、零忽略，其中真实引擎 Host 362 项；
应用 326 项 Rust 测试及默认 Tauri 编译通过。严格 workspace Clippy、应用双配置 Clippy、
生成物只读检查与应用 Rust 1.90 MSRV 均通过；manifest 单测 177 项、真实 CLI 进程测试 8 项通过。
新增模块及改动函数已格式化；全量测试使用 -j 1 限制本机链接内存。
12 项架构守卫通过，包含 root Rust 1.88 MSRV 与真实应用调用方编译；
真实 SDK 作者链路的 Host 1 项与 CLI 2 项测试通过，Android ARM64 的 core/Host 编译通过。
文档链接检查 113 个文件零问题，数量声明零冲突（保留既有 3 项不可自动检查项）。
Android 未进行设备运行验证。

## 验收边界

本轮没有改变具体域名守卫策略，也未实现所有动态函数族、IPv6 范围或进行中 IO 的撤销取消。
未修改前端和 IPC 类型，不重复未受影响的前端验证；未执行发版，也不代表 M2 完成。
