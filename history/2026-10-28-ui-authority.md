# 2026-10-28 · 插件页面的持久授权代次

这是 [Starter 本机 UI 联调](./2026-10-28-starter-local-ui.md) 的后续；整体 D2–D4 和两个官方插件仍未完成。

## 发现与实现

真实 Starter 经过安装、授权和启用后打开页面，再调用生产 `plugins_disable`，旧令牌仍能读取 `self.actions`。
旧实现只比较进程内 nonce 与打开时的版本，没有读取之后的启停和授权变化。

存储层现在给插件分配持久 `authority_revision`。数据库内的全局单调分配器避免删除重装后重复，
插件各自保存当前代次；另一插件的授权变化不会撤销本插件页面。
启用、信任、权限行及活动版本的变更通过 SQLite trigger 在原事务内推进代次，
非活动候选版本和运行健康信息不影响当前页面；同版本显式 reload 也推进代次。
批量 `record_grants` 改为单事务，第二条授权写入失败时，第一条及代次一并回滚。

页面只可在插件已启用且已同意授权时创建，权限与代次从同一 SQLite 读事务取得。
每次 RPC、ready 和资源访问均比较当前持久事实；失效令牌不会在重新启用、重新授权或同版本重装后复活。
这是请求开始时的授权检查，已开始的外部操作仍按各自的任务取消契约处理，不宣称撤销能回滚外部副作用。

页面窗口标签使用插件摘要与独立文档 id，标签不包含 RPC nonce。
并发打开在最终发布 nonce 与窗口记录时串行，复用同一个有效文档；新文档使用新标签，
旧窗口延迟触发销毁不会移除新会话。失效窗口保留清理记录，原生桥每秒请求销毁，失败可重试。

资源 handler 现在使用框架提供的 WebView label，不能借另一插件已打开的 origin 获取资源；
同时修正它读取 `AppState`、而实际 manage 的类型为 `Arc<AppState>` 的不匹配。

授权验证改为只读；只有显式 ready 报告才标记页面已安装监听器。
资源读取和后台清理检查不再提前标记 ready。

本程序未发布，直接修改创建新库的 schema；没有添加旧开发数据库兼容路径，旧开发 profile 需重建。

## 验证与边界

- 存储层 293 项测试通过；新增覆盖跨连接、重开、另一插件隔离、同版本 reload、删除重装、事务回滚、计数器溢出和读快照一致性。
- UI registry 113 项测试通过，验证授权检查不会更新 ready。
- Core、daemon、作者 CLI 的受影响调用方测试通过，包含实际 CLI component/UI 校验入口。
- 真实 Starter 测试覆盖生产安装→授权→启用→页面资源/RPC，再经过停用再启用、reload、权限撤销与恢复、卸载重装，检查旧 nonce 和资源均拒绝；旧窗口迟到销毁后新文档仍可调用。
- 应用并发打开、未启用/未信任、过期 nonce 替换、清理重试与显式 readiness 单独验证；桌面完整检查记录保存在本轮 target 日志。

这些测试不等于真实 WebView 渲染或手机到电脑操作验收。
共享插件控制面、完整任务取消、更新/迁移的混合代次恢复仍按 D2–D4 继续推进。
