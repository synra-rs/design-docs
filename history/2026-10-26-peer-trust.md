# 对端凭据持久绑定与授权代次

日期：2026-10-26。对应 [04 §7.2、§8.2](../04-wire-protocol.md)、[17 §5](../17-storage-and-config.md)、
[ADR-017](../20-adr.md)；当前实施状态只以 [19 D1](../19-roadmap.md) 为准。

## 实现范围

`synra-net::authentication::pairing` 在同一 TLS 配对机制实例内依次交换 `consent` 与 `stored` 记录，
两阶段均校验版本、阶段、双方 id 和原始 RFC 9266 会话绑定，整个实例受原 60 秒窗口约束。
`ConsentExchange` 保持受限连接，成功或失败完成后关闭，不能变成业务流；业务使用另行认证的连接。

`synra-core::peer_trust::PairingTask` 在用户确认前认领持久任务，收到双方同意后提交准备日志，
再在数据库锁外交换双方存储回执，最后短事务复核任务快照与本机凭据登记，原子提交授权和完成标记。
`pairing_attempt` 是单槽任务日志，`peer_trust` 才是授权事实；重启不从准备日志自动授权。
旧任务清理只取消自己的请求代次，解除配对在同一事务撤销旧元数据、token、凭据授权和活动任务。

`PeerApproval` 捕获授权代次，宿主必须将它与新建业务连接一起保留，每个业务请求都调用 `allows`，
检查当前数据库授权代次、实际 TLS 双方证书和消息来源；即使使用相同证书重新配对，旧代次也不再有效。
逐请求查询按 peer id 索引进行，不复制或解析整个授权列表；批量加载证书的验证在数据库锁外完成。

两端最终提交不构成分布式原子事务：一端可能在发出准备回执后提交失败，另一端已提交；
失败端继续拒绝业务，不根据已发出的回执或重启日志推断授权，生产接入还需处理两端状态不一致的交互。

## 本轮纠正

- 提交前获取时间的外部回调原本处在数据库 guard 的参数求值中，现改为锁外采样，测试用 `try_lock` 验证。
- 原 SQLite `synchronous=NORMAL` 的注释混淆恢复一致性与提交持久性，现统一使用 `FULL`，并检查真实连接重开后的设置。
- 旧设计要求拒绝配对后复用连接，与独立 ALPN 和 RFC 9266 单实例结束后关闭要求冲突，当前规范改为关闭后重新建链。

SQLite 设置依据：[官方同步文档](https://www.sqlite.org/pragma.html#pragma_synchronous)。
FULL 增加同步成本，本轮未测吞吐收益，也未模拟物理断电；测试证明配置和事务行为，不证明硬件执行了持久写入。

## 验证

定向测试覆盖真实 loopback TLS、生产共享服务入口和真实 SQLite 文件：

- 核心 13 个测试：成功后重开恢复、未准备与准备日志均不授权、旧任务与替代任务隔离、取消与过期的两处提交边界、
  相同证书重新配对后旧授权失效、本机身份与实际 TLS 本机证书变化、同意及授权提交失败、数据库读取失败默认拒绝。
- 存储 6 个测试：独立连接并发认领唯一赢家、授权容量及同 id 换证拒绝、触发器注入写失败后的事务整体回滚、
  本机登记变化后旧授权和任务失效、真实写连接重开仍为 FULL，以及内存库和弱化同步设置不能报告持久成功。
- 网络配对 24 个测试，较前一轮增加 5 个：本机持久化失败、持久化阶段零预算及过期、阶段与身份等字段再次校验、
  对端负回执和缺失回执的总超时，保留原有邀请、证书固定、ALPN、重放及部分 TLS 记录边界验证。

阶段门禁通过：工作区全量测试与 doctest、工作区全部目标 Clippy（`-D warnings`）、所有修改 Rust 文件格式检查、
12 项架构守卫（含工作区 Rust 1.88、应用调用方编译及 91 份文档链接检查），应用默认 Tauri 编译及 317 个无默认 feature Rust 测试。
在全量测试后的存储配置检查补充中，只重跑受影响的存储 6 个及核心 13 个测试，并完成上述最终 lint 和守卫，未重复不受影响的全量测试。
Android `aarch64-linux-android` 核心 `cargo check` 通过，网络库测试程序 `--no-run` 链接通过；没有设备运行结果。

本轮未修改前端，未重复执行前端测试或构建；这些结果不用于证明生产安全链路已完成。

## 剩余工作

两个生产宿主仍走原 TCP 与 token 流程，尚未调用本服务，也没有生产逐消息授权入口；本轮不能证明生产配对已安全。
Android 持久密钥后端、运行验证、可信带外邀请的产品交互、显式身份修复、Hello 身份复核及生产撤销流程仍待完成。
测试中的密钥后端替身只用于登记夹具，不是可用的加密文件后端，也不构成平台密钥持久性证据。
