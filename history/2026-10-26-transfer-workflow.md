# 共享完整发送流程（2026-10-26）

本记录承接[宿主认证接入调查](./2026-10-26-host-authentication.md)中确认的应用文件发送缺口。
当前实施状态以 [19 §0.2](../19-roadmap.md) 为准，传输契约见 [04 §8.4](../04-wire-protocol.md)。

## 行为与边界

原应用发送只把文件块写入链路并立即统计 delivered，没有提议、完成或接收方确认；
原内存测试也只读块，因此不能证明生产 listener 能完成接收。
原共享发送器另会在超时后返回部分事件；这次整体替换其成功条件，未保留旧行为的兼容分支。

应用将准备好的 TransferSender、任务进度回调和取消查询交给 core 的 send_prepared；
daemon 的 send_file 与 send_bundle 也委托同一流程，只有收到同一传输且摘要一致的完成确认才成功。
超时、取消和对端 abort 分别返回结构化错误，取消与超时会尝试发送有界的终止通知。
插件包的安装结果仍与文件摘要确认区分，后续结果等待也会检查取消与预算；
缺少安装结果不能单凭文件确认推断插件安装或启用成功。

窗口始终最多保留四个未确认块，按新增确认释放槽位；拒绝越界块数、未发送块的确认和确认回退。
修复的是窗口约束，未扩大既有窗口参数；普通报告不再产生保存全量 missing 列表的事件，真实修复才记录 Resend。
进度来自接收端确认，重复报告不会刷新 idle 预算；IO 等待按剩余预算收窄，返回时恢复调用者的超时覆盖值。
链路读预算也覆盖半帧和心跳循环，超时保留已读字节，允许后续继续解码。
daemon 在登记连接后释放 Host 锁再执行文件 IO，接收方回调验证此时可获取发送方 Host 锁。

## 验证

新增共享发送测试覆盖小缓冲区背压、故意丢弃首块后的修复、窗口不得被未发送块的确认放大、
错误摘要与错误传输 id、等待确认时取消、缺少确认的 idle 超时、已到期的总预算和重复进度不得续命。
另有半帧超时后续读不丢字节的链路回归；应用原成功测试已改成双端完整协议。

应用新增三个测试，从生产发送命令或发送入口经过真实文件数据库、固定证书 TLS 和生产共享 listener：
一百万字节文件完成并逐字节一致、接收端拒绝不计 delivered、传输中取消关闭任务且保留用户源文件。
这些夹具预置授权，不证明首次配对或原生密钥登记；身份流程的证据仍属于 D1。

阶段门禁通过：工作区全部包的测试、集成测试及 doctest，工作区全部目标 Clippy，
全部修改 Rust 文件的格式检查，12 项架构守卫（含 Rust 1.88、应用调用方及 94 份文档链接），
应用 322 个 Rust 测试、全部目标 Clippy、默认 Tauri 编译，以及 Android 核心交叉编译。

检查按影响范围续跑：首次工作区检查在 core 的错误分类断言处中止，已通过的前置包不重跑；
修正后 core 的 796 个单测中 795 个通过，另一个失败定位为两个旧 sender 测试共用按进程 id 命名的临时文件，
会互相删除文件，已改成独立 TempDir，定向复核两项均通过。
其余工作区包、core 四个集成测试目标和先前尚未运行的 doctest 分别补齐；
错误摘要、半帧及心跳预算的新增回归均通过，不把首次失败的退出码当作通过证据。
应用默认编译完成后，后续核心内部修复未改动 Tauri 专用代码，沿用该检查结果；
本轮未修改前端，未执行前端测试与构建。

## 剩余范围

D2 仍有完整更新、授权、撤销和启停服务的业务边界收敛工作；D1 的首次配对交互、身份修复及 Android 原生后端仍未完成。
本轮不包含吞吐基准、延迟分位数优化、物理设备运行验证或发版。
