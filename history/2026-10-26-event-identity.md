# 完整插件身份与事件范围授权

日期：2026-10-26；对应 [10 §2.7](../10-capability-and-sandbox.md)、[协议](../04-wire-protocol.md) 与 [M2](../19-roadmap.md)。

## 原缺口及实际修复

HostCalls 将完整 PluginId 转成去发布者、去包名前缀的 slug，再判断事件 owner。
同名的 @acme/chat 与 @other/chat 因而可以互相冒充；新增生产入口回归先复现第二次调用错误地成功。
事件现使用 _plugin.<完整 @scope/name>.<topic>，保留发布者、完整包名及包名前缀，不接受旧短格式。
协议构造、解析、序列化、接收分类、模式和 manifest 使用同一身份规则；项目目录短名与授权身份分开。

event-emit 导入只判断函数族是否有范围，逐次调用则校验完整 owner 和实际事件 capability。
合法名称的身份越权返回 capabilityDenied、记拒绝审计；畸形名称返回 badArgument，均没有宿主效果。
通配权限不能突破命名空间；内核可发事件白名单仍由原协议检查负责。

事件和模式限制为 240 字节，为最长 event:subscribe: 前缀预留 16 字节；完整包 id 可达 128 字节。
新增边界测试覆盖最大包名、恰好达到上限、超过上限、旧短格式、同名发布者、前缀别名与转义输入。
manifest 同时校验事件语法及长度，避免只验证字符串前缀而接受不能解析的声明。
借用 owner 做语法校验，避免解析事件时分配又丢弃一个 PluginId；分配守卫覆盖真实长事件名。

## 验证范围

真实 WIT 组件实际调用 event-emit，覆盖精确权限、不同事件、跨发布者、包名前缀别名、撤销后的新会话、通配和旧格式拒绝。
断言七次 Host 尝试只有两次到达宿主；CLI 的真实组件声明检查也使用完整事件名。
客户端、应用注入拒绝用例及公开 manifest schema 示例同步调整，未修改 TS IPC 或二进制字段布局。
公开 schema 保留原 v1，按未发布事实更新已审查快照，并增加合法、畸形及长度边界验证。
