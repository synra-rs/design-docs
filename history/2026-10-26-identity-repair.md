# 显式本机身份修复（2026-10-26）

承接[本机登记](./2026-10-26-device-credentials.md)中的丢钥拒绝路径。
现行契约见 [17 §5](../17-storage-and-config.md)，完整范围见 [19 §0.2](../19-roadmap.md)。

## 实现

共享 repair 仅接受当前登记公开证书的确切 SHA-256 指纹。
保留 device id，但以一个 FULL/WAL 事务替换未就绪证书、撤销全部对端授权和列表元数据、
清除未完成配对；随后在数据库锁外写入并读回新私钥，最终仍复核同一登记。
同一事务的撤销写入失败会整体回滚，不留下新旧身份混合状态。
写入前失败不恢复旧授权，写入后报错只允许恢复已记录的同一把新钥。

schema 21 保存最多 16 个旧公开证书与后端的待清理记录，不保存私钥。
修复返回新凭据与独立的清理结果，清理失败不等同于换钥失败，也不能恢复旧授权。
删除成功还须读回确认不存在，再提交删除记录；删除后报错或提交中断可幂等重试。
无法访问的其他后端保留在队列中，队列满时进一步修复在改动身份前拒绝。

故障注入揭示仅靠 SQLite CAS 不够：另一次修复若在先前 secret.set 返回前清理候选槽位，
旧写入可能随后重新创建已被清理的密钥。登记、修复、清理因此共用数据库旁的 OS 文件锁，
立即拒绝竞争者，不在密钥 IO 期间持有 SQLite 锁；进程退出释放锁，空锁文件永久保留。
该锁也覆盖原有首次登记，竞争中的登记现在明确返回 OperationBusy。
Windows 的锁竞争错误通过库提供的原生错误码识别，不能只依赖 WouldBlock 分类。

CLI 新增 identity status、identity repair --expected-fingerprint SHA256 和 identity cleanup，
通过 daemon 的本地控制握手进入共享流程；拒绝未知字段和跳过本地握手。
状态展示公开登记及待清理数量，ready 只表示持久登记完成。
修复结果明确 restartRequired，当前运行实例持有的旧证书和连接由数据库授权门拒绝，
不声称已热更新 listener；两端须重新配对。应用依赖锁文件同步新增的文件锁依赖。

## 验证

存储测试覆盖跨连接 CAS、待清理队列上限、撤销失败的整体回滚及清除握手前预留。
共享服务注入写入前后失败、损坏写入、丢弃写入、删除前后失败和未实际删除，
重开真实数据库后验证同一新钥恢复或继续拒绝，并确认清理不会删除当前密钥。
独立测试进程验证真实文件锁的跨进程互斥，并在持锁时直接进程退出，验证 OS 释放锁。
生产 mTLS、Hello 和业务帧测试验证换钥后旧连接持续拒绝，重新配对仅开放新连接。
Windows daemon 生产 Kernel 命令使用独立文件数据库和随机测试身份调用原生后端，
验证错误指纹拒绝、新钥写回、明确重启要求、重新初始化认证网络及再次拒绝旧指纹。
测试清理只删除该随机测试证书对应的原生槽位。

阶段门禁通过：工作区全量测试、集成测试和 doctest，包含 core 808 项、store 275 项、
daemon 256 项、CLI 109 项及 control 65 项；受影响五个包的全部目标 Clippy 与修改文件格式检查通过。
应用默认 Tauri 编译和后端全量 320 项通过；Android 核心交叉编译通过，
12 项架构守卫包含声明 MSRV 1.88、应用调用方及 97 份文档链接。
存储版本属性测试的固定旧范围也扩展为当前 schema 与相邻未来版本，
定向复核后复用其余已通过结果，避免后续迁移持续遗漏新版边界。
本轮未改前端或 JS 协议，不重复其未受影响的检查。

## 剩余范围

修复入口目前要求已有公开登记；本机身份或登记记录缺失的恢复、应用修复交互、
Android 原生后端及设备运行、其他平台恢复和完整业务链路仍未完成，D1 保持开发中。
Android 编译检查不证明文件锁在设备上的运行行为，不证明原生密钥后端可用。
本轮不包含发版或性能基准。
