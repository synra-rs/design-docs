# 未发布阶段的 API 约定

日期：2026-10-26；落实 [ADR-021](../20-adr.md) 与 [19 D5](../19-roadmap.md)。

## 触发与修改

意图结果改为明确的成功或失败变体后，全量测试中的旧 api-guard 要求给枚举加 non_exhaustive。
该要求来自错误的发布前提：STABILITY.md 把多个从未发布的 Rust crate 写成 Published=yes，并要求破坏性变更走 major 和迁移说明。
按用户已确认的未发布事实，直接修正约定；没有为通过旧门禁给新结果类型加兼容性标记。

STABILITY.md 现记录所有 Rust 库、宿主和工具均未发布，接口和数据格式可直接重构；同步实际调用方、协议镜像与测试即可。
AGENT.md 和协议 crate 的 Cargo 注释同步修正，不要求旧格式适配、双版本实现或为未发布接口增加 major。
工作区事实同时修正为 26 个成员，其中 17 个库、2 个宿主及 7 个工具。

## 保留的检查

api-guard 不再提供 Stable、SemiStable 等提前冻结等级，也不再要求兼容性注解或禁止只读 DTO 的具体容器。
库按 Domain / Adapter 声明诊断边界；领域公共错误仍不能直接暴露未分类的依赖错误。
所有列出源码仍解析 Rust 语法，文件或目录读取失败不能静默跳过；适配层的底层错误由实际调用方映射。
测试从真实 Cargo workspace metadata 读取库成员，与守卫目录和 STABILITY.md 双向比较，防止少列、多列或重复。
原有多行公共签名、嵌套错误、私有辅助函数及语法失败的 AST 回归继续保留。

依赖方向、协议无 IO、内核无 GUI、能力闸门、路径沙箱、资源预算、热路径分配预算和真实宿主调用方检查保持强制。
未发布只改变兼容性义务，不降低安全及行为验收。

## 验证与范围

新增门禁回归验证未发布接口允许闭合枚举、DTO 容器和必选 trait 方法；领域未分类错误、非法语法和不可读工作区仍拒绝。
api-guard 的 7 项单元测试、4 项集成测试及全目标严格 Clippy 通过；真实 CLI 扫描当前源码，覆盖 17 个库。
专门检查已不再计入删除的旧兼容性规则测试；整阶段 Core 全工作区 3,601 项测试及全目标严格 Clippy 通过。
12 项仓库守卫通过，包括 Core MSRV 1.88、实际 App 调用方和 Core、设计库及公开文档库共 120 份文档的链接检查。
本轮同时验证 App 的 335 项 Rust 测试、默认 Tauri 编译及 MSRV 1.90 全目标编译；完整调用链证据见[意图结果记录](./2026-10-26-intent-outcomes.md)。
实际 api-guard 扫描当前工作区；对外发布前再依据真实消费者逐项声明兼容范围，未创建版本、tag、发版或部署流程。
整体工作继续以 [19](../19-roadmap.md) 为准，D5 完成不等于 M0–M6 或其他设计修订完成。
