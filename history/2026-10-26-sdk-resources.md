## 真实失败与修复

此前 Rust 作者链路仍使用仓库内的 SDK，编译宏通过 `../../wit` 读取仓库根资源。
将实际 SDK 源码复制到独立目录后，真实 CLI 构建在读取该路径时失败；
此前通过的构建不足以证明 SDK 能脱离源仓库使用。

SDK 现在读取自身 `wit/synra-plugin.wit`，由生成器从根契约派生，带有禁止手改的标记。
根契约仍是唯一可编辑来源，ABI 绑定仍由固定的 wit-bindgen 在编译时生成。
公开契约版本、Host 接口和 world 常量也使用同一次生成的元数据，消除手写副本。

真实模板测试复制 SDK 源码与资源，并从实际 workspace 表展开继承元数据；
模板 Rust 源与 SDK 库源码均未替换，原 `../../wit` 查找位置明确不存在。
测试经实际 CLI 构建、组件编码、生产 PluginSet 装载和调用，
继续覆盖缺少导出和 Rust 编译错误两种失败重建，旧组件字节均保持不变。
此证据是隔离源码依赖验证，不代表 Cargo 注册表包或发布流程已经验证。

## 生成与只读检查

旧 `--check` 只比较能力表，且选项在第一个位置时会被误当成源文件路径。
它无法阻止 SDK 资源、导入常量或 Host trait 过时。

生成器现在共享一份完整计划，覆盖能力表、可读报告、Host trait、SDK 导入常量与包内 WIT：

- 先完成解析与所有渲染，再开始写文件，解析或渲染失败不会部分替换旧产物。
- 只读检查收集所有缺失或过时文件并返回失败，不修复、不创建文件。
- 生成仅写变化的文件，比较时归一化 CRLF，避免 Windows 检出造成假漂移。
- CLI 接受源路径前或后的 `--check`，真实二进制集成测试覆盖两种位置与缺失资源。
- CI 在可能生成 Host 表的构建之前先检查全部产物，保留原有工作流触发与发布编排。

这不承诺多文件写入在磁盘 IO 失败时整体原子化；重新生成与检查仍是修复和确认方式。
