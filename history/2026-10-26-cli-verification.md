# CLI 实际二进制与声明覆盖验证

日期：2026-10-26；对应 [作者契约](../15-plugin-sdk.md)、[ADR-024](../20-adr.md)、
[验证策略](../21-testing-strategy.md) 与 [M2](../19-roadmap.md)。

## 原缺口与失败证据

原 Target::read 只读取固定 plugin.wasm 的长度，从未解析组件；导入向量恒空，
报告只给出 warning，进程仍以成功退出。
真实命令负例已复现：任意八字节内容会被判为 artifact 通过，错误不能仅靠 manifest 单测暴露。
原 CLI 的 provided/refused 名称表使用旧接口，与生产 Host 的函数名称也不同。

## 当前实现

Target 用 Result 保留读取或校验失败，不再让空向量同时表示“未读”与“零导入”。
读取路径来自 manifest，拒绝绝对路径、父目录穿越和 canonicalize 后越界；
manifest 最多读取 1 MiB，组件使用宿主体积上限，增长中的文件再以有界读取复核。
静态文件类型检查先于打开，以免将普通文件入口用于 FIFO 等特殊节点。
UI 必须存在声明的 entry，文件数、字节数与目录项遍历均有上限；读取错误不再跳过，
目录链接不能逃出 bundle 或回到根目录。

组件先解码实际导入，再以生产 Host 表判断已知函数；
未知接口、WASI、资源或错误接口版本保留并拒绝，惰性值类型接口不作为能力调用。
静态 WIT targets 检查验证完整嵌套函数体及接口的导入/导出类型关系；
build 与 verify 共用此步骤，而非分别只比较三个导出名称。
声明覆盖使用 host_surface::undeclared_imports，与生产闸门共享规则；
这仅证明 manifest 声明足够，不代表用户同意或装载时的实际 grant。

CLI 携带自身派生 WIT，不读取源仓库外部路径；
生成器现在覆盖六项输出，新增 CLI 契约资源，检查仍先于 Host 构建且保持只读。
此前五项输出的验证记录保留为 [当时状态](./2026-10-26-sdk-resources.md)。

## 测试方式与范围

普通命令测试从真实文件经二进制入口验证，使用生产 WIT 派生的可审查组件，
覆盖有效及无效组件、不同 artifact 名称、缺少能力声明、零导入、
错误 Host/Guest 签名、缺失导出、版本与资源导入、无效嵌套 opcode 及输入边界。
UI 用例包含自定义目录与 entry、缺失入口、超大文件、平台目录链接的拒绝；
子命令设有截止时间，轮询仅用于观察进程，不以等待时长判断产品行为。
打包、静态索引与上传计划测试的伪模块改为有效的无 Host 导入组件，
签名篡改用附加合法 custom section 改变字节，继续验证签名拒绝而非提前被无效格式挡住。

真实 Rust Guest 门禁额外要求实际 SDK 产物和生成模板经过命令 verify，
随后仍通过生产 PluginSet 装载与调用，不能用派生 dummy 的类型验证替代真实 Rust 作者链路。

## 后续发现与验收边界

源码复核发现，host_surface::permits 与 HostCalls::call 都直接用函数族模式查询授权集：
例如 network-fetch 的门为 network:fetch:*，而实际声明可能仅为 network:fetch:api.github.com。
当前实现没有区分“可使用这个函数族”与“本次参数是否在允许范围”，
因此范围型声明可能在装载或调用前被误拒；需要以真实限定目标、越界目标和撤销路径作专项验证与修正。
本次 verify 复用既有共享规则，不据此宣称范围授权已经完整可用；下一阶段应同时收敛装载与调用语义，
不能只放宽 CLI 或取消运行时目标约束。

静态检查不运行 Guest 构造器，不证明任意组件的引擎执行、目标平台或性能预算。
包身份、声明实现语义、UI 完整构建、安装与用户同意等剩余验收仍见路线图，
本阶段不代表完整 verify、M2 或整体目标完成。
