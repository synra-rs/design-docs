# 日志函数的级别范围授权

日期：2026-10-26；对应 [10 §2.6](../10-capability-and-sandbox.md)、[M2](../19-roadmap.md) 与 [验证策略](../21-testing-strategy.md)。

## 问题与契约

日志函数也曾用族标签 log:* 直接查询权限，导致 log:info 在导入和逐次调用时被拒。
两个新增回归测试先复现失败；现将支持级别的导入可用性与实际级别授权分开。
支持 trace、debug、info、warn、error；通配权限可以覆盖这些级别，实际参数不能是通配或自造级别。
两个宿主共用 HostCalls 的检查，不另建日志权限实现；保持具体能力拒绝详情及拒绝审计。

## 定向证据

四项原生回归测试验证具体级别、通配、非法级别、JSON 转义、撤销及宿主效果与审计数量。
真实组件由主 WIT 编码，实际调用类型化 log 导入；info 获准、warn 越权与撤销后新会话被拒、通配 error 获准。
日志的 WIT 返回 void，拒绝通过 trap 报告，并断言错误包含 capabilityDenied，避免把 ABI 错误当作拒绝通过。
每个 trap 场景使用新实例；测试确认每次实际 Host 调用计数，以及只有两次获准日志到达宿主。
真实 CLI 组件同时携带 log:info 与域名/方法权限，八项二进制验证测试通过。
Host/CLI 全目标严格 Clippy 和五项定向 Host 测试通过。

## 分配回归与定向门禁

workspace 首次门禁捕到导入检查分配 3 次，超过 hot_paths 既有 1 次预算。
原因是每个候选级别先 format 再解析；现对常见具体和整族授权直接检查已解析的 grant，
一般多段模式仍使用共享 matcher，具体调用也直接解析静态能力名，避免构造临时格式串。
分配守卫扩展到具体级别、双星、未知级别和其他域六个场景，既有预算不变，并增加零分配断言。
十项 hot_paths 测试及五项日志定向测试再次通过；六个常见导入可用性场景均满足零分配断言。
测试注释明确该预算测量导入可用性；它不代表完整 Host 调用、JSON 或实际日志输出的分配。
验证策略增加热路径改动同步跑该定向 target，避免等到全量门禁才发现同类问题。
